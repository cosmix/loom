## Rules `claude plugin validate` enforces (verified on 2.1.295; validate fails the load otherwise)

- `$` never crosses an import. Every `$` call is spelled literally (`$.noun.event(...)`) inside a hook callback or inside a function declared in the same file as that hook; `$` passed to an imported function, destructured (`const { clock } = $`), indexed (`$['ui']`) or `$.state` used as a value is refused. Imported modules export pure functions on plain values (parse, clean, format, row layout); JSX helpers may take the element table `$.ui.resolve(e)` returns. A module that needs `$` may register its own hooks by exporting `wire(on)` and calling `on(...)` itself.
- At most ONE hook with no matcher per event name in the whole plugin, across files: `on("tool.call") is registered twice without a matcher` fails validation, and the same for `session.start`, `agent.spawn`, `turn.step` and `turn.complete`. So all `session.start` work (polling, command registration, timer restarts) sits in one hook, all `tool.call` work (agent counting and the guard feed) in one, all `turn.complete` work (agent status and the gauge refresh) in one, each feature behind its `userConfig` flag. Hooks with distinct matchers coexist: `command.run` `{ command: 'loom' }` and `{ command: 'loom-agents' }`; `ui.render` `{ component: 'AbovePrompt' }`, `{ component: 'Pane', requestId: 'loom' }` and `{ component: 'Pane', requestId: 'loom-agents' }`.
- `turn.step` must be an async generator.
- Every `$.state` key must be declared in `types/index.d.ts` under `PluginState['loom-ui']`; an undeclared key fails validation. State values are JSON and never `undefined`: omit optional fields instead of setting them to `undefined`. Write shared values (`agents`, `denials`) through `update()` from `'claude-code'`, which reads, applies and writes with a version check and retries on a miss; parallel subagents' hooks write `agents` concurrently.
- A `.json` file cannot be imported, and a module holding `import()` does not load.

Suggested split, within those rules: `register.tsx` (every hook that spells `$`, plus same-file helpers that take `$`), and pure modules `snapshot.ts` (parse, clean), `format.ts` (durations, token counts, percentages), `band.tsx` / `panes.tsx` (layout from plain values and the resolved element table), `agents.ts` (record updates as pure functions), `guards.ts` (marker matching). Keep each file under 400 lines and each function under 50.

## Manifest

`plugin.json`: `name` `loom-ui`, `version` `0.1.0`, a one-line `description`, `author` `{ "name": "loom" }` (without it `validate --strict` fails), `"types": "./types/index.d.ts"`, and `userConfig` with four fields `stageBand`, `contextGauge`, `subagentTracking`, `guardFeed`, each `{ "type": "boolean", "title": "<short>", "description": "<one line>", "default": true }` (`title` and `description` are required; the type is one of `string`, `number`, `boolean`, `directory`, `file`). `register(on, options)` receives the values with defaults filled in, and a `/config` change reloads the module with new options. A field set to `false` switches its feature off entirely: a hook used only by that feature is not registered; inside a shared hook its branch does nothing.

## Snapshot polling (in the one `session.start` hook)

- Read `const stageId = await $.env.get('LOOM_STAGE_ID')` and `const loomBin = await $.env.get('LOOM_BIN')`. Poll only when `stageId` is non-empty AND `loomBin` is an absolute path (starts with `/`); otherwise never poll (out-of-stage mode). Those two are the plugin's only env reads.
- Start polling without awaiting it: `session.start` is awaited before the first prompt, so it must not wait on a 3 s poll. Kick off one poll and keep the `Timer` that `$.clock.every(5000, …)` returns. A `Timer` is an object with a `cancel()` method (the declaration's `TimerCall` returns `Timer`), not a function: stop one with `timer.cancel()`, never `timer()`. Every timer handle (the 5 s poller, the 1 s agent clock, the 5 s agent reconciler) lives in a module-level `let` in `register.tsx`, never in `$.state` (state is JSON); set the variable to `undefined` right after `cancel()`, and start a timer only while its variable is `undefined`, so there is never a second one. A hot reload re-runs the module, so the variables start `undefined` again exactly when the engine has cancelled the old timers.
- Each poll: `await $.process.run([loomBin, 'hook', 'ui-snapshot'], { timeoutMs: 3000 })`, written with that argv on one line. That is the ONLY `$.process.run` call in the plugin (the surface script counts it). No `cwd` or `env` option: the child inherits the claude process's environment and working directory, which is how the snapshot proves membership.
- Never overlap: skip a tick while a poll is in flight. `$.process.run` REJECTS when the executable cannot start and on timeout (a non-zero exit resolves with `exitCode`), so wrap the run in `try/catch/finally`: a rejection counts as a failed poll and the in-flight flag resets in `finally`.
- `parseSnapshot(stdout: string): Snapshot | null` (pure, in `snapshot.ts`): `JSON.parse` in try/catch, then check the type of EVERY field common.md lists (numbers finite and >= 0, strings, booleans, arrays of the right element shape), accepting `null` for every field common.md's "Nullable fields" list names; `schema !== 1` is `null`; an out-of-stage `reason` outside common.md's nine codes is `null`; arrays longer than 64 are cut; every string goes through `clean(text, max)`, which removes whole ANSI escape sequences (`ESC [ ... final byte` and other `ESC`-introduced sequences), then remaining C0/C1 controls, bidi and zero-width characters, and truncates with an ellipsis. A snapshot with `in_stage: false` is valid and means "not a stage session".
- Store the parsed value in `$.state` (`snapshot`). On a failed poll (rejection, non-zero exit, `null` parse) keep the previous snapshot and count failures; after 3 in a row, mark it stale (the band shows `loom: snapshot unavailable` dim) until a poll succeeds. After an `in_stage: false` answer keep polling every 5 s: a new session's first polls can answer `outside-worktree` before loom records its worktree.
- Hot reload (`loom update` rewriting `~/.claude/skills/loom-ui`) drops the module's timers, keeps `$.state` and fires `session.start` again, so the poller restarts by itself. When state holds a `running` agent record, the same hook first reconciles once with `$.agent.list()` (Subagents below; the agents may have finished while no timer ran), then starts the 1 s and 5 s agent timers only if a record is still `running`.

## Bands above the prompt (band.tsx)

One `ui.render` hook on `{ component: 'AbovePrompt' }` draws up to two sections, sized to `e.props.bodyColumns`, parts dropped from the right when a line does not fit. While `e.props.hasSurvey` is true, or when neither section has anything to show, it returns `next(e)` and draws nothing of its own.

**Stage section (`stageBand`).** Drawn ONLY while the latest snapshot in state has `in_stage: true`. Out of a stage, in a session whose `LOOM_STAGE_ID` is unset, or after a poll answered `in_stage: false`, nothing of it is drawn, not even a placeholder. Line one:

    loom ▸ <stage.id> · <status> · try <retry_count+1>/<max_retries+1 or 4> · <elapsed> · <model>/<effort> · deps <merged>/<total> · review <rounds> rounds, <open> open

A `null` part (elapsed, model, effort) is left out. Then, when `attention` is non-null and `automatic` is false, a red line `⚠ <label>: <note or command>`; when `daemon.stalled`, a yellow line `daemon tick <n>s ago`; when the snapshot is stale (below), a dim `loom: snapshot unavailable` in place of line one's live parts. These are drawn text only: the plugin raises no notification for them. A `Hide` button whose `onPress` sets a session `$.state` flag `bandHidden` (through `update()`) hides the stage section only; no `ui.press` hook is needed, and if one is added it must return `next(e)` for every press it does not own.

**Subagent section (`subagentTracking`; in and out of stages).** Drawn whenever at least one tracked subagent is `running`, in any session. One row per running agent, newest first, at most 6, then `+<k> more`:

    <type> "<description>" · <elapsed> · <model>/<effort> · ctx <tokens>/<ceiling> <pct>% · <last tool>

- `<elapsed>`: `now - startedAt`, as `42s`, `3m05s`, `1h02m`; it measures the current run (a resumed agent restarts `startedAt`, see Subagents). While any agent runs, one `$.clock.every(1000, …)` timer updates a `now` value in `$.state` so the rows redraw each second; call `.cancel()` on the `Timer` it returned when none runs, and never start a second one.
- `<model>`: the model of the agent's latest `turn.step` (fallback: `agent.spawn`'s `r.model`), with a leading `claude-` removed. `<effort>`: that step's `effort` (a level string as is, a number as `<n>`); the `/<effort>` part is left out when the step carried none.
- `ctx`: the agent's resident context (see Subagents). The denominator, in a stage: the snapshot's `subagent_ceiling_tokens`. Out of a stage: `(await $.session.usage()).context.window` when the agent's latest step model equals the main loop's latest step model (both recorded from `turn.step`); otherwise only `ctx <tokens>` with no denominator or percent, because Claude Code exposes no window per subagent. Percent is `Math.floor(100 * tokens / denominator)`; it is yellow at 60% and red at 90%. Tokens print as `43k` (thousands, rounded down).
- `<last tool>` is the first part dropped when the row is too wide.

## Context gauge (`contextGauge`)

In stage only (outside one Claude Code already shows its own context). After each successful poll and on `turn.complete` of the main loop (no `agentId`): read `(await $.session.usage()).context.tokens`; it is absent before the first response and right after compaction, and then the gauge shows nothing. With the snapshot's `ceiling_tokens` (0 means no gauge), call `$.ui.status('ctx 412k/800k 51%')` with a `⚠` prefix at `warn_tokens` and `‼` at `red_tokens`. When any subagent is running, append `· <n> agents, max <pct>%`, the highest subagent utilization against `subagent_ceiling_tokens`. No toast and no notification on a band change: the prefix is the signal. `$.ui.status(undefined)` clears the status when the session leaves the stage.

## `/loom` pane

Register `loom` in `session.start` with `$.command.register({ name: 'loom', description, immediate: true })` ONLY when polling starts (stage id set and `LOOM_BIN` absolute); a session outside a stage gets no `/loom` command. `immediate: true` matters: without it a command typed mid-turn waits for the turn to end, and a stage session is almost always mid-turn. The `command.run` hook on `{ command: 'loom' }` answers without calling `next`: it opens a pane with `$.ui.open({ id: 'loom', title })` and answers `{}`. When the latest snapshot says `in_stage: false`, it answers `{ text: 'Not in a loom stage session (<reason>).' }`, where `<reason>` is one of the nine codes `parseSnapshot` already validated; never any other snapshot text, because a `{ text }` answer becomes a transcript row the model reads. The pane is drawn by the `ui.render` hook on `{ component: 'Pane', requestId: 'loom' }` with sections: Stage (every `stage` field), Context (tokens now, warn / red / handoff = ceiling / backstop), Dependencies and Dependents (id, status, merged), Checklist (numbered acceptance lines, `acceptance_total` when it exceeds the list, wiring and contract counts, verification status, review rounds well-formed / total, open findings, blocker summary and next action), Attention (label, note, command shown as text to copy, never run), Daemon. The pane has no buttons that act on loom.

## Subagents (`subagentTracking`; works in and out of stages)

Track subagents in `$.state` `agents`, keyed by `agentId`, written through `update()`:

- `agent.spawn`: `const r = await next(e)`; when `r` carries an `agentId`, record `{ type: e.subagentType, description: clean(e.description, 60), model: r.model, parentAgentId?: e.parentAgentId, isTeammate, startedAt: await $.clock.now(), status: 'running', steps: 0, toolCalls: 0 }` (optional fields omitted when absent); return `r` unchanged.
- `turn.step` (async generator): `const result = yield* next(e); try { … } catch {} return result`. The bookkeeping runs after `yield*` completes, so every chunk is forwarded unchanged. It touches only records `agent.spawn` created (engine forks and workflow agents carry agent ids with no spawn and no list entry): with `e.agentId`, set `model = e.model` and `effort = e.effort` when present, and when `result.usage !== null`, `context = input_tokens + cache_creation_input_tokens + cache_read_input_tokens` and `steps += 1`; without `agentId` (the main loop), store `e.model` as `mainModel`. A step for a tracked agent whose record is not `running` means a message resumed it under the same id (the declaration's `AgentStatus` doc: a finished agent "a message may yet resume ... under the same id"; each run of its loop is one turn): set `status: 'running'`, set `startedAt` to `await $.clock.now()` (elapsed measures the current run), delete `endedAt`, and start the 1 s and 5 s agent timers if their variables are `undefined`.
- The one `tool.call` hook, for a tracked `e.agentId`: count the call and set `lastTool = e.tool` BEFORE awaiting `next(e)`; the guard feed runs after it (below).
- `turn.complete` with a tracked `e.agentId`: `reason` `answer` gives `done`, `aborted` gives `killed`, `refusal` and `error` give `failed`; set `endedAt`. A teammate (`isTeammate`) goes idle after every turn, so its record is never ended by `turn.complete`.
- Every 5 s while any agent is `running` (a second `Timer`, cancelled when none runs), reconcile with `$.agent.list()`: `completed`, `failed`, `killed` end the record; `pending`, `waiting` and `idle` count as running; an agent missing from the list is finished (the list keeps an agent only until the engine drops its task).
- Keep at most 64 records. When a spawn would make 65, drop the finished record with the oldest `endedAt`; when all 64 are running, drop the running record with the oldest `startedAt` (the band shows at most 6 rows, and the newest spawn is the one the person is watching).
- `/loom-agents` (registered in every session with `immediate: true`; its `command.run` hook on `{ command: 'loom-agents' }` opens the pane and answers `{}`) shows a row per agent, running and finished: type, description, status, elapsed (frozen at `endedAt` once finished), model and effort, ctx tokens with the denominator and percent rules of the subagent section, steps, tool calls, last tool, plus a guard-denial count per agent.

## Guard feed (`guardFeed`; works in and out of stages)

Inside the one `tool.call` hook: `const r = await next(e)`. Take the denial text as `r.deny ?? (r.isError ? r.text : undefined)` (a settings `PreToolUse` deny reaches plugins as `{ isError, text }`; a plugin beneath may answer `{ deny }`; `text` is optional). When one of its first 5 lines contains `LOOM: BLOCKED` (covers `LOOM: BLOCKED -` and the pre-commit hook's `LOOM: BLOCKED COMMIT -`), `⛔ BLOCKED:`, `BLOCKED: Commit contains`, `LOOM_CONTROL_ERROR:` or `LOOM_HOOK_ERROR:`, then `$.ui.toast('loom blocked <tool>[ in <agent type>]: <first non-empty line after the marker, cleaned, 120 chars>')`, `$.ui.log` the first 3 cleaned lines, and append `{ at, tool, agentId?, line }` to `$.state` `denials` (keep 20). Return `r` unchanged. An ordinary tool error with none of the markers in its first 5 lines does nothing (loom's own hook test output prints marker text deep in its output). Toasts and log lines never reach the model.

## Allowed surface (enforced by scripts/check-loom-ui-surface.sh)

Hooks: `session.start`, `ui.render`, `ui.press`, `command.run`, `tool.call`, `agent.spawn`, `turn.step`, `turn.complete`. Calls: `$.ui.resolve`, `$.ui.status`, `$.ui.toast`, `$.ui.log`, `$.ui.open`, `$.ui.invalidate`, `$.state.get`, `$.state.set` (`read()`/`update()` show up as these two), `$.clock.every`, `$.clock.now`, `$.command.register`, `$.env.get`, `$.process.run`, `$.agent.list`, `$.session.usage`. Env reads: exactly `LOOM_STAGE_ID` and `LOOM_BIN`. Nothing else (`$.ui.notify`, `$.ui.ask`, `$.ui.copy`, `$.ui.notice`, `$.prompt.*`, `$.model.*` are all violations).

The script (POSIX `sh`, `set -eu`, needs `claude`, `jq`, `rg`):

1. `root` = the repository root from the script's own path (`root=$(cd "$(dirname "$0")/.." && pwd)`); `plugin="${1:-$root/claude-plugins/loom-ui}"`; `export CLAUDE_CONFIG_DIR="${CLAUDE_CONFIG_DIR:-$root/loom/target/claude-cfg}"`. It works from any cwd.
2. `claude plugin validate --strict --json "$plugin"` must exit 0; keep its JSON.
3. Parse `.contents[].notes[]`. The real note format (2.1.295) names the registered module and folds imports into it: `./register.tsx hooks: session.start, ui.render{component=Pane, requestId=loom}, turn.step`, `./register.tsx calls: $.process.run (via poll), $.ui.open`, `./register.tsx env reads: LOOM_STAGE_ID, LOOM_BIN`, plus other kinds (`env writes:`, `state reads:`, `state writes:`, `gating hook without .catch:`, `calls: nothing on $`) the script ignores. Matcher braces contain `,`, so strip them before splitting:
   - hooks: `jq -r '.contents[].notes[] | select(test("^[^ ]+ hooks: ")) | sub("^[^ ]+ hooks: "; "") | gsub("\\{[^}]*\\}"; "") | split(", ")[]'`
   - calls: `jq -r '.contents[].notes[] | select(test("^[^ ]+ calls: ")) | sub("^[^ ]+ calls: "; "") | gsub(" \\(via [^)]*\\)"; "") | split(", ")[]'`
   - env reads: the same pattern on `env reads:`.
   Compare each item with the allowlists above; print every offender as `loom-ui surface violation: <item>`.
4. `rg --count-matches -g '!*.test.ts' -g '!*.test.tsx' -g '!fixtures' '\$\.process\.run\(' "$plugin/hooks"` summed over its `path:count` lines must be exactly 1 (`--count-matches` counts two calls on one line as two; `-c` would not), and that one line must contain `[loomBin, 'hook', 'ui-snapshot']`; validate lists `$.process.run` once whatever the argv, so the argv rests on this check. Each failure prints a `loom-ui surface violation:` line.
5. Run every check even after a failure. Fail when any violation was printed, and also when step 3 parsed zero hooks or zero calls (a parser that matches nothing must not pass). Otherwise print `loom-ui surface ok: <n> hooks, <m> calls` and exit 0.

## Tests (`*.test.ts` / `*.test.tsx` beside the modules; kit from `claude-code/testing`)

`claude plugin test` discovers every `*.test.ts` / `*.test.tsx` under the plugin, prints `(pass) <name>` or `(fail) <name>` per test, exits 1 on any failure and also exits 1 when there are no tests. The stage gate requires a `(pass)` line for each of `[c1]` to `[c11]`, so every required case's test name starts with its tag, e.g. `[c4] gauge text and warn prefix`; extra tests are welcome.

How the kit works (read the declaration's testing section before writing): tests are `test(name, [{ options }], async ($, on) => …)`; the test's own `on` hooks sit BENEATH the plugin and answer the ops the plugin calls; `mock` offers only `clock`, `store`, `env` and `session`, and there is no spy. An op nothing answers is dropped silently (`$.ui.toast`, `$.ui.status`) or makes an awaited call reject so the whole plugin hook is skipped (`$.env.get`, `$.command.register`, `$.ui.open`), and `$.ui.mount` of a plugin that returns `next(e)` rejects without a `ui.render` floor. So one shared helper registers, kept under `hooks/fixtures/` (e.g. `hooks/fixtures/kit.tsx`) because that folder is test-only: W3's embed skips it, so it is never installed, and the surface count ignores it: `mock.clock(on)`; `mock.env(on, vars)` (an unlisted variable is unset); `on('process.run')` answering `{ exitCode, stdout, stderr: '', isStdoutTruncated: false, isStderrTruncated: false }` and recording each argv; `on('session.usage')`, `on('agent.list')`, and `on('command.register')` answering `{ command }` and recording names; recorders for `ui.status`, `ui.toast`, `ui.log`, `ui.open` and `ui.notify`; and a sentinel floor `on('ui.render', async ($, e) => { const { Box, Text } = $.ui.resolve(e); return <Box><Text>ENGINE-DEFAULT</Text></Box> })` so "draws nothing of its own" is asserted as "only `ENGINE-DEFAULT` is shown". Seed an in-stage snapshot through the real path: env `{ LOOM_STAGE_ID: 'loom-ui', LOOM_BIN: '/opt/loom/bin/loom' }`, `process.run` answering `JSON.stringify(SNAPSHOT_FIXTURE)`, `await $.session.start({ cwd, surface, isInteractive: true })`, then `clock.settle()`. Mount with `$.ui.mount({ plugin: 'loom-ui', surface, component, props, requestId })`. Loop every UI test over `['terminal', 'desktop'] as const`.

Required cases:

1. `[c1]` `parseSnapshot` accepts `SNAPSHOT_FIXTURE`, the out-of-stage form `{"schema":1,"in_stage":false,"reason":"no-stage-env"}`, and a fixture copy with every nullable field set to `null`; rejects `schema: 2`, a numeric `stage.name`, a missing `context`, an unknown `reason` code, non-JSON; a name holding `\u001b[31m` and `‮` comes out containing neither U+001B, nor U+202E, nor `[31m`.
2. `[c2]` The band draws the fixture's stage id, status and `NEEDS INPUT` line. With `LOOM_STAGE_ID` unset and one subagent running, it draws the subagent row and no `loom ▸` text; with the out-of-stage snapshot and no agent running, only `ENGINE-DEFAULT` shows.
3. `[c3]` With `stageBand: false` passed as a non-default option (`test(name, { options: { stageBand: false } }, body)`), only `ENGINE-DEFAULT` shows while the fixture snapshot is in state (configuration propagation: a test at the default cannot tell a feature that ignores the option).
4. `[c4]` Gauge text for 312000 of 800000 is `ctx 312k/800k 39%`; at 480000 it carries the `⚠` prefix; crossing it records no toast and no `ui.notify`.
5. `[c5]` Subagent row: a spawn, then a `turn.step` with `agentId`, model `claude-sonnet-5-5`, effort `high` and usage `{input_tokens: 1000, cache_creation_input_tokens: 2000, cache_read_input_tokens: 40000}`, with `agent.list` answering that agent as `running`, then 65 s of mocked clock: in stage the row reads `sonnet-5-5/high`, `1m05s` and `ctx 43k/800k 5%`; out of stage, with the main loop's step on a different model, it reads `ctx 43k` with no percent; with the same model and a mocked window of 200000, `ctx 43k/200k 21%`. After the agent's `turn.complete`, the plugin's `now` state value stays unchanged across `clock.advance(5000)` (the 1 s timer was cancelled; the mock clock exposes no timer list).
6. `[c6]` Polling: after a successful first poll, a `process.run` answer that resolves after 12 s of mocked clock gives exactly one spawn over two 5 s ticks; three exit-1 answers in a row mark the snapshot stale; a `process.run` hook that throws once counts as one failed poll and the next tick polls again.
7. `[c7]` A spawn plus a `turn.step` with usage `{input_tokens: 1000, cache_creation_input_tokens: 2000, cache_read_input_tokens: 40000}` shows `43k` in the `/loom-agents` pane; a `turn.step` for an agent id never spawned, with usage `null`, yields the floor's chunks and returns the floor's result unchanged.
8. `[c8]` Guards: a `classic.PreToolUse` deny whose reason starts `LOOM: BLOCKED - Cross-worktree access detected` raises a toast naming the tool (the kit's `$.tool.call` raises `classic.PreToolUse`, and a deny ends the call with the errored result); an ordinary failing tool raises none; a denial whose marker sits on line 7 raises none. In every case the result `$.tool.call` returns deep-equals the result the floor produced (the hook observes and returns `r` unchanged).
9. `[c9]` Out of stage (`LOOM_STAGE_ID` unset): the `process.run` recorder sees 0 calls, and `command.register` sees only `loom-agents`.
