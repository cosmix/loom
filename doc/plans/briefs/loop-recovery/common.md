# Execution contract

Read this file and the assigned worker brief in full. The plan is `doc/plans/PLAN-loop-recovery.md`. Brief paths and exact ownership are also recorded in `ownership.json`. The source root was renamed on 2026-09-13; all hook implementation writes use `loom-hooks/`.

Every standard implementation unit uses `loom-codex-forwarder`, `--model gpt-5.6-sol --effort xhigh`, and an explicit foreground Bash timeout of 600000 ms. This is the user's deliberate model choice, including routine tests and fixes. The stage's main agent coordinates and verifies; it does not implement. Workers never spawn agents, run git, write orchestrator state, or edit outside their assigned paths. The orchestrator checks the changed-file set after every worker. Record discoveries immediately through `loom memory note`/`decision`; do not edit the knowledge corpus or use auto-memory.

Each worker may run at most one narrow check once, and should skip it when uncertain. The orchestrator runs all acceptance checks after every worker has stopped. Read edited predecessor files directly: source-graph results reflect the branch point. Briefs are instructions, not authority to change unrelated files. A newly discovered consumer needs a concrete ownership amendment and a disjoint Sol follow-up unit before the gate, never an unowned edit or silent deferral.

Keep files at most 400 lines and functions at most 50 lines. Where an existing file is already larger, extract the changed responsibility into its assigned new helper namespace rather than grow it. Each worker owns new helper modules only under the explicit namespaces in `ownership.json`; register them through that worker's assigned parent module. No extra dependency is planned. If one becomes necessary, use `cargo add` or `bun add`, with manifests and lockfiles assigned to one serial worker first.

After feature workers finish, spawn a fresh Sol ledger unit with this brief and the stage's changed-file list. It owns only `loom/maintainability-baseline.txt`, reads the affected source and `loom/tests/maintainability/{baseline,scanner}.rs`, and reconciles reduced or eliminated existing entries. It must not add exemptions or raise a ceiling. Unresolved growth returns to the responsible feature owner for extraction; the ledger unit cannot mask it. It reports its exact edits, assumptions and unresolved items, then stops. The main agent subsequently runs the canonical gate, which includes maintainability.

Acceptance has no access to host daemons, local listeners or host Unix sockets. Tests inject scratch roots and joined in-memory transports; never resolve the real project's runtime directory. Always set `TMPDIR=/tmp/loom-loop-checks` for commands that create fixtures. This short, pre-existing, external non-repository directory avoids both Unix socket pathname length and tests accidentally inheriting a git ancestor. Every fixture creates its own unique child and joins child processes before cleanup. No test may silently skip the core identity, authorization, state-transition or dispatch assertions.

The report's measured 902 calls and two concurrent watchers are regression inputs, not a performance budget. Model-facing wait output is one initial result and one terminal notification per wait owner; duplicate callers receive an existing-wait identity without starting another loop. Internal clock-driven polling may continue without model/tool round trips. Tests assert this invariant rather than wall-clock speed.
