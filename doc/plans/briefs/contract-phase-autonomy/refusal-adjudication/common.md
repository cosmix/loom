# refusal-adjudication: shared context

Read this first, then your own brief, then `doc/loom/knowledge/mistakes/adjudication-autonomy-deadlock.md` (its prevention rules bind every lifecycle path here). The plan's Decisions 8-12 are authoritative. Paths are relative to `loom/` unless they start with `../`. Line numbers are from plan time (before stage 1 merged); locate each symbol with `rg -n` before editing.

## Rule

A stage never waits on a human for something loom or an agent can resolve, and no agent settles a disputed constraint itself. A refused contract freeze therefore becomes a dispute that loom files and an independent adjudicator decides and justifies. Nothing in the contract phase parks the stage on `WaitingForInput`; only an `AskUserQuestion` the writer asks does, as for every session.

## How a refused freeze flows today (verified at plan time)

- The writer's CLI (`commands/stage/contracts/freeze.rs`) checks changed paths, file existence and (after stage 1) the scaffold and chain, then writes a relay ticket. `keep_outcome` (about L232-240) clears the refusal file `$LOOM_SCRATCH_DIR/contract-freeze-refused.txt` once the ticket is written and records it on any error. `LOOM_SCRATCH_DIR` is `<scratch_root>/<session-id>` (`orchestrator/terminal/native/wrapper/host_env.rs:22`), so a fresh writer never sees an old file.
- The inbox drain (`orchestrator/core/inbox_drain/apply.rs`) runs `require_owner` first (about L153-155, L209-226), then `freeze::settle` (`inbox_drain/freeze.rs`); a refusal parks through `park_refused_freeze` (L50). An accepted request becomes a Freeze host job; `host_verify/freeze.rs::apply_freeze_result` (L270) parks on a failed, interrupted or daemon-stopped run and on unreadable reports or binding (`park`, L381).
- `stage_service/contracts.rs::check_stage` (about L241-247) accepts a freeze only in `Executing | WaitingForInput`, so no freeze lands while the stage is `NeedsAdjudication`.
- `commit-guard.sh` (Stop hook, about L278-329) calls `loom stage waiting` when the refusal file exists. The Stop hook fires at every turn end, including while background subagents run (`commit-guard.sh:11`), which is why it must not file anything.

## Pinned types and names

- `DisputeKind::FreezeRefusal { problems: Vec<String> }` in `src/models/dispute.rs` (enum at about L83-113, `#[serde(tag = "kind", rename_all = "kebab-case")]`, so the tag is `freeze-refusal`). `problems` is the refusal's problem list split on `\n`, empty lines dropped, each flattened with `context::untrusted::inline_safe`, at most 32 entries of 1 KiB. Problems from the writer's own refusal file carry the prefix `writer-reported: ` (the tick step adds it); the daemon's own problems carry none.
- `impl DisputeKind { pub fn filed_by(&self, session: SessionType) -> bool }`: `FreezeRefusal` only by `SessionType::Contract`; every other variant by any session type except `SessionType::Contract` (Knowledge sessions relay criterion disputes, `relay/matrix.rs:87-91`).
- Admission (`stage_service/dispute_kinds.rs::confirm`): load the session record that `stage.session` names (`fs::session_files::load_session_exact`) under the dispute lock and refuse when `!kind.filed_by(session.session_type)`; a stage with no current session admits every kind but `FreezeRefusal` (an operator filing). This needs no session plumbing through the socket, relay or spool callers, because that record names the stage's owner and the transports fix the caller: the socket admits `FileDispute` from Stage sessions only (`daemon/server/self_service.rs` `DISPUTE_KINDS`) and the relay refuses `(Contract, FileDispute)`. The transport entries `handle_file_dispute` (socket and relay) and `handle_file_dispute_identified` (spool, `fs/stage_request/apply.rs:90`) refuse `FreezeRefusal` before `confirm` with "freeze-refusal disputes are filed by loom only" and write nothing, which also closes the operator's token-authenticated socket path. Both keep their signatures and delegate every other kind to a private `file_dispute_inner(work_dir, stage_id, kind, reason, evidence_commit, request_id)` holding today's body. For `FreezeRefusal` also: a v2 standard stage with contracts, no freeze record (`verify::contracts::store::load_freeze` is None), status `Executing`; skip `check_frozen`.
- Budget: `DisputeTally.freeze_refusal_disputes` (`src/models/stage/dispute_budgets.rs`, `#[serde(default)]`), cap `MAX_DISPUTES_PER_KIND` (3). `exhausted` runs before `spend`, so filings 1-3 are admitted and the 4th escalates.
- Filing entry point (W2 builds, W1 calls): `pub(crate) fn file_freeze_refusal(work_dir: &Path, stage_id: &str, problems: Vec<String>, request_key: &str) -> Result<FreezeRefusalFiling>` in `stage_service/dispute_kinds.rs`, going through the private `file_dispute_inner` with `request_key` as its request id (so a retried filing reuses one `request.md`, `receipts.rs`). `enum FreezeRefusalFiling { Filed(String), Declined(String) }`: `Declined` for an admission refusal (logged at warn level by the caller, never retried as an error); `Err` only for an I/O failure. The 4th filing never reaches it: W1's tick step checks `dispute_budgets::exhausted` first, retires the writer, then calls W2's `pub(crate) fn escalate_freeze_refusal(work_dir: &Path, stage_id: &str, problems: &[String], unretired: Option<&str>) -> Result<()>` (same file), which writes `NeedsHumanReview` through `dispute_store::escalate_to_human_review` (`pub(super)`, so only `stage_service` can call it) with the reason in "Flow" step 6, plus the survivor detail when `unretired` is set.
- Daemon refusal record (W1 builds): `verify::contracts::refusal::{record_daemon_refusal, take_daemon_refusal, daemon_refusal}` over `.loom/work/contracts/<stage>/refused.json` = `{ "session_id", "problems", "at" }`, written atomically; `Err` on a failed write so the drain and host apply retry.
- Tick step (W1 builds): `Orchestrator::dispute_refused_freezes(&mut self)` in `orchestrator/core/event_handler/freeze_refusal.rs`, called from `run_tick` (`orchestrator/core/run.rs`) right before `self.hand_off_frozen_contract_phases()` (about L112). Plan Decision 9 is its spec.
- Verdict JSON for `freeze-refusal` (the existing `DisputeVerdict` fields; no new struct fields):

```json
{"verdict": "reject", "reasoning": "<evidence-cited reason>", "citations": [{"source": "...", "quote": "..."}], "instructions": "<what the next writer must change>"}
{"verdict": "accept", "reasoning": "<evidence-cited reason>", "citations": [{"source": "...", "quote": "..."}], "plan_patch": {"patches": [{"field": "harness", "op": "insert", "index": 0, "value": "tests/fixtures/**"}]}}
{"verdict": "needs-more-evidence", "questions": ["..."]}
```

Copy the citation object's exact keys from `parse_citations` in `orchestrator/adjudication/verdict.rs` (the shape above is illustrative). Storage: `Reject { citations, reasoning: reasoning + "\n\n### Instructions\n\n" + instructions }`; `Accept { plan_patch: PlanPatch { inner: {"patches": [...]} }, citations, reasoning }` (`PlanPatch.inner` is a flattened object, so a bare array cannot be stored). `patches[].field` is one of `contracts`, `harness`, `acceptance`; each entry is decoded with `plan_patch::decode_patch`. Entries apply in array order, one `amend_plan` call each with dispute id `<dispute>.<k>` (`k` the entry's position), and each index is read against the field as the earlier entries left it; validation replays the same order over a copy of the stage's fields, so an index out of range for the running state is refused. Validation for `freeze-refusal` runs at recording with the stage and its worktree (see W2) and returns `Err` to the judge, never a coercion to needs-more-evidence: empty reasoning or no citation (`grounding`, `verdict.rs:170-189`); reject without instructions; accept without patches; any other field; an `acceptance` entry that is not `replace` of an index whose current entry `verify::contracts::format_gate::is_format_check` recognises, with a value that parses as an acceptance criterion whose command is itself a format check; a harness value (verbatim string) for which `verify::contracts::collection::harness_source_matches` finds production source among the worktree's tracked and untracked files under working_dir (`changes::harness_files`-style listing) or the derived scaffold paths (`collection::stage_scaffold`, both `CreateRoot` alternatives); no locatable worktree refuses.
- `AmendmentField::Harness` (kebab `harness`), value a plain glob string taken verbatim (`ParsedAmendmentValue::Harness(String)`, trimmed, empty refused, never parsed as YAML).

## Flow after this stage

1. The writer runs `loom stage contracts freeze <id>` and stops.
2. Refusal at the CLI: the writer may fix and retry in the same turn. If it goes quiet with the refusal file present (Decision 9's quiet rule: 300 s since the file and the session's latest heartbeat, no live child), the tick step files it.
3. Refusal at the daemon (relayed admission, or the host contract run): the drain or host apply writes the daemon refusal record; the same tick's step files it.
4. Stage → `NeedsAdjudication`; the verdict-apply path retires the writer (`retire_disputing_agents`, session-type agnostic, runs before apply in `core/verdict_apply.rs`), applies the verdict, writes the feedback notice, requeues. `first_agent_kind` (`orchestrator/core/stage_spawn.rs:44-60`) starts a Contract writer on the same worktree because no freeze exists; its signal carries the notice.
5. A retired writer is not a crash: `contract_phase_event` requires `Executing` and `stage.session` naming the writer (`orchestrator/monitor/detection.rs:334-338`), so the contract respawn budget is not charged.
6. The 4th refusal: the tick step retires the writer, then writes `NeedsHumanReview` with reason "contract freeze refused 4 times; adjudication could not resolve it: <last problems>. Decide with: loom stage human-review <stage-id>".
