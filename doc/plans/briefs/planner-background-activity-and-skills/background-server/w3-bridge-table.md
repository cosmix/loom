## Design (settled)

1. **Parsing, `transcript/notification.rs`** (new, `pub mod notification;`): `parse_task_notification` and `TaskNotification` as in `common.md` (interim when the summary ends with "is waiting on its own background work"; the status from the `<status>` element only), plus the evidence the bridge's table reads, all built from record values without panicking on a malformed one:
   - a launch from a `tool_result` and its `toolUseResult`: `status == "async_launched"` with `agentId` is an agent launch; a `backgroundTaskId` (W1's `agent_state::background_task_id`) is a shell launch; the result's `tool_use_id` comes with both;
   - a `TaskStop` result: `toolUseResult.task_id` with `task_type` (`local_bash` or `local_agent`);
   - the hand-back: a user record with `origin.kind == "peer"`, `origin.handback == true`, `origin.senderTaskId` and `origin.handbackReportText`;
   - the fork launch: a `system` `local_command` record whose content holds `<forked-skill-launch>{agentId, skillName, description}</forked-skill-launch>`.
   `records.rs` only calls into this module and stays at most 400 lines: the notification record still opens a turn as `SelfStarted` and now carries its parsed body; the hand-back stays skipped as a chat item but carries its evidence; the fork-launch record carries its evidence. Put the record-to-evidence code in `notification.rs`, never in `records.rs`.
2. **Mapper, `transcript/mod.rs`.** `RecordMark` gains one variant for background evidence with the record's `at`. The launch label is the calling `tool_use` block's `input.description`: keep a small map from `tool_use_id` to that description, filled when the mapper sees an `Agent`, `Task` or `Bash` `tool_use` block, capped with `cap_chars` like every stored string. Remove `RecordMark::SubagentFinal`, `Assistant.end_turn` and their uses (dead once the synthetic stop goes). Tool rows keep their status logic; A6 renders the table's state over them.
3. **Table, `bridge/background.rs`** (new, `pub mod background;`): `BackgroundTask`, `TaskKind`, `TaskState` of `common.md`, and `pub struct BackgroundTasks` owned by each `Session` (a field of `Session` or `Flow`). Its inputs: the spool events `SubagentStart`, `SubagentStop`, `Stop`, `SessionStart`, `SessionEnd`; the mapper's background evidence with its time; each raw subagent line with its agent id (through `AgentProgress::observe`, W1); an agent's meta (`agentType`, `description`, `finished`); `agents_killed`; and `reevaluate(now, stall_budget, debounce_secs)`. Each input returns what changed: whether the table changed, and the agent ids that ended for the first time. Rules, all from A-D2 and A-D3:
   - launch evidence creates an entry or fills the fields it lacks, keeping the earliest `started_at`; the same evidence twice changes nothing;
   - a `Stop` list adopts an unknown `type: "shell"` entry (no `tool_use_id`, label from the list's `description`, `started_at` the Stop's `received_at`); it never adopts an unknown `subagent` entry; the latest `Stop` list and its `received_at` are kept, and an unended entry started before that `received_at` and missing from the list ends `Done`, also when the entry is created after the list was read; `SubagentStop` lists are never read;
   - a notification gives the outcome (`completed` to `Done`, `failed` to `Failed`, `killed` or any other status to `Stopped`) and fills `tool_use_id`, also for an entry a list already ended (`Done` becomes `Failed`); the interim variant ends the agent like `finished`, and later records of that agent reopen it to `Running`; a notification for an unknown id adds an ended entry;
   - a `TaskStop` result ends a known entry `Stopped`;
   - for known agent ids only, the hand-back, a subagent `tool_result` record with `toolEndsTurn: true`, meta `finished: true` and a `SubagentStop` each end the agent `Done`; a `SubagentStop` for an unknown id (an internal fork, `agent_type: ""`) is ignored;
   - agent states: the fold's `Generating` and `Unknown` read `Running`, `ToolWait` reads `ToolWait`; `agent_state::stall_reason` with the stall budget marks an unended agent `Stalled`; later evidence ends or reopens it; shells are never `Stalled`;
   - `steps` is the fold's assistant-entry count, `last_tool` its last tool, `report_preview` the hand-back's `handbackReportText` (capped);
   - an ended shell never reopens; a `Stop` list never reopens or re-creates an ended entry; an interrupt changes nothing; `agents_killed` clears every entry; `SessionStart` with source `startup`, `resume` or `clear` clears the table, `compact` keeps it; `SessionEnd` clears it;
   - times come from record timestamps and spool `received_at`, never from the clock at ingest; only `reevaluate` takes `now`.
4. **Driver and session.**
   - `apply_event` hands every spool event to one table call near its top and loses the `SubagentStart` arm and the `SubagentStop` branch, so it gains no lines (cap 50). `on_agent_stop`, `AgentWatch`, `Flow.agents`, `stop_stalled`, `SUBAGENT_STALL` and `stall_after` go. `Inner.stall_budget: Duration` (600 s, a named constant beside its doc) takes `stall_after`'s place; `tick_session` passes it, with `Utc::now()` and `agent_state::DEFAULT_DONE_DEBOUNCE_SECS`, to `reevaluate` in its timers step.
   - `ingest_agent` gives each raw subagent line (parsed as JSON) to the table before its early return; the meta file's fields reach the table once, when `AgentFeed::classify` first reads it (carry them in the batch beside the agent's lines).
   - One helper publishes a change: `BridgeEvent::Background { id, tasks }` when the table changed, then one `BridgeEvent::SubagentStopped { id, agent_id }` per agent id that ended for the first time. The table's per-id "stopped once" flag makes it once per agent id, whatever end evidence arrives later and whether or not the agent reopened.
   - `on_idle`'s close gate reads the table's blocking count: agent entries in `Running` or `ToolWait`. Shells, `Stalled` and ended entries do not block.
   - `apply_mark`'s `SelfStartedTurn` path is unchanged; the background mark is a separate arm beside it. `AgentsKilled` also clears the table.
   - `confirm_prompt` (flow.rs) ignores a `prompt` whose trimmed start is `<task-notification>` or `<agent-message`: neither confirms a pending delivery. Keep a committed `background_prompt` helper and its tests if the operator committed them, with the rule live.
5. **The counter goes.** `StateMachine` loses `subagents` and `subagents_running()` and every arm that touched them; `SessionView` loses `subagents_running` (`model/mod.rs`, `publish.rs`, `model/tests.rs`, `pressure/tests/fake.rs`). `summaries/rebuilds/session.rs` gains `BridgeEvent::Background { .. } => {}`.
6. **Meta reading.** `AgentFeed::classify` keeps `agentType`, `description` and `finished` beside what it keeps today, through `pub struct AgentMeta` and `pub fn read_agent_meta(subagents_dir, agent_id)` in `agents.rs` (the one size-bounded, no-follow reader), re-exported as `pub use agents::{read_agent_meta, AgentMeta};` from `registry.rs`. W4 calls it to build the planner token groups.
7. **Recovery.** A recovered session re-reads its spool and transcripts from offset 0 (`bridge/recovery.rs` `resume`, `plan_session/spool.rs` `Tail::new`), so the table is rebuilt by the same inputs; it is never persisted.

## Traps

- One `SubagentStopped` per agent id, ever: emit it from the table's "ended for the first time" result, never from an input handler.
- The order of reads is not the order of events: an entry created after the bridge read a later `Stop` list is checked against that list when it is created.
- `Stop` and `SubagentStop` payload ids are untrusted: cap them, and never build a path from them.
- `reevaluate` runs every driver tick (200 ms in production): it must not allocate per entry when nothing changed, and it emits only on a state change.
