## Markdown renderer rules

`web/src/plan/markdown/` turns a document into React elements from an mdast tree (`mdast-util-from-markdown` with the GFM extension, `markdown.tsx`; `render.tsx` and `inline.tsx` walk the nodes). It is the planning app's main XSS surface, so these rules hold and `markdown.test.tsx` plus `markdown.contracts.test.tsx` pin each with adversarial inputs (scripts, event handlers, `javascript:` links, images, HTML in tables and code):

- **No raw HTML, no `dangerouslySetInnerHTML`.** An `html` node renders as inert text (`rawHtmlText`, class `md-raw`), never markup.
- **One link path.** Every link, autolink and image target goes through `resolveLink(fromPath, href)` (`files/address.ts`) and renders through `SafeLink`; nothing else builds an `href`. The allowlist is `http:`, `https:` and `mailto:` to an external host (`external`), a `#anchor`, or a path that stays inside `doc/` after decoding and resolving `..` (`doc`); a target that leaves `doc/` is `outside` and anything else, `javascript:` and `data:` included, is `text`.
- **Images are links.** An `image` node never becomes an `<img>`: the app loads nothing a document points at. It renders its alt text (or URL) as a `SafeLink`, or as plain text inside a link.
- **Entity-sensitive cases live in test strings.** `oxfmt` rewrites character references in `fixtures/*.md`, so those adversarial inputs stay inline in the test file ([why](../mistakes/plan-server-delivery.md#web-test-tooling-hid-or-created-defects-in-file-mode-2026-10-27)).
- The reading column and `.md` prose are capped at 70ch (`concept.css`, `markdown/markdown.css`) and tables scroll in their own region; open accessibility and layout gaps are in [the file-mode follow-ups](../architecture/plan-server.md#file-mode-follow-ups).

## CodeMirror lazy boundary

The editor, merge view and diff views use CodeMirror 6 (`@codemirror/{state,view,commands,language,search,lang-markdown,lang-yaml,merge}`, `@lezer/highlight`). It must stay out of both initial bundles:

- Only `web/src/plan/editor/codemirror.ts` imports `@codemirror/*` or `@lezer/*` statically. Everything else reaches it through `loadCodeMirror()` in `editor/load.ts`, one `import("./codemirror")` per page whose rejected promise is cleared so the next call retries.
- `web/scripts/bundle-rules.json` states the rule for `scripts/bundle-check.mjs`: `index.html` and `plan.html` forbid `node_modules/@codemirror/**`, `node_modules/@lezer/**` and `src/plan/editor/codemirror.ts` in their chunks, and forbid the text `cm-editor`; `index.html` also forbids `src/plan/**`. `plan.html` forbids the terminal (`@xterm`, `components/terminal`), so plan code imports only leaf graph modules (`thread-edge`, `lib/graph`) and never `components/graph/stage-graph`.
- `load.test.ts` and `editor.contracts.test.tsx` scan sources for static imports of `@codemirror/`; the contract uses `import.meta.glob ?raw` and requires `codemirror.ts` to import statically and `load.ts` to import dynamically, so it cannot pass vacuously. `@lezer/` is covered by the bundle rules and a `load.test.ts` scan.
- `EditMode` renders through a data router (`createMemoryRouter`) on the default Jotai store from `@/state/store`, because `saveDoc` and the drafts read that store and `useBlocker` needs a data router. Drafts are written through `useDraftWriter` (`editor/draft-writer.ts`): 500 ms debounce, flushed on `beforeunload`, hidden visibility, blur and unmount, cancelled on discard. `saveFlow` is pure; draft clearing is signalled through state, and drafts are kept when the text changes during an in-flight save.
- Every editor, merge and diff view holds a colour-scheme compartment (`EditorView.darkTheme`) reconfigured by a `MutationObserver` on the `html` class. `theme.ts` uses only CSS variables (`theme.test.ts` checks each `var(--x)` exists in `index.css`, `tokens-light.css` or `tokens-dark.css`, read as `?raw` with vitest `css.include`) and no colour literal.
- Selections in the editor and in diffs carry provenance for Add to chat (`editor-provenance.ts`, `diff/diff-provenance.ts`); a side-by-side selection carries a `side`, and the before side gets a null anchor. `AddToChat` clamps to the viewport, flips above, hides off-viewport and re-measures on capture-phase scroll and resize (`attachments/floating-position.ts`).

## Concept Mode Test Rules

- A contract test for a module that does not exist yet loads it through a variable-specifier dynamic import (`/* @vite-ignore */`) with local types. A literal import of the missing module fails vite import analysis at collection and turns every contract red for one reason (`concept.contracts.test.tsx` loads `open-state.ts` this way).
- The contract fetch stub answers `/api/doc` by the doc-relative path (leading `doc/` stripped), so a `docRel` path or a repo-relative `?path=` both work; marks are found by any `aria-label` matching `<title>: doc/...md`; a dashed chip accepts `data-dashed` on the link, an ancestor or a descendant; the empty-state offer is an `aria-disabled` (not `disabled`) button described by exactly "Available once chat is built" while `canAuthor` is true.
- Test files named `.ts` cannot hold JSX (the oxc transform fails); use `createElement`. `bun run typecheck` is blocked for subagents by the subagent verify guard, so the orchestrator runs it.
- A test reads CSS through an `@/...css?raw` import, never `readFileSync(new URL(..., import.meta.url))`. An assertion on a passive-effect side effect (`scrollIntoView`, focus) after `findBy*` goes inside `waitFor` ([the race](../mistakes/test-concurrency-and-fixtures.md#an-assertion-on-a-passive-effect-right-after-findby-is-a-race-2026-10-28)).
- `FoldCap`'s accessible name stays exactly `Fold` on both caps of a run (`web/src/plan/concept/fold-handle.tsx`): a run has two (`data-side` start and end), so tests query `getAllByRole("button", { name: "Fold" })`, and a per-run name breaks them; the caps are told apart with `aria-describedby` on the run's labelled group.
- The reading-column harness (`reading-column-harness.tsx`) serves placed pages (`pages` and `loadPage`), so a column test that places a cited summary page in the store survives `useCitedPages` prefetching it; a 404 stub would drop the placed page (`failedState`) and the run would read "Loading".
- To shrink a test file over 400 lines, move non-assertion setup into helpers; moving whole tests into a new file raises a test-integrity event ([the event](../mistakes/plan-server-delivery.md#moving-tests-into-a-new-file-raises-a-test-integrity-event-2026-10-28)).

## Chat Panel and Review UI Rules

- **Mirror, parse, key.** Wire types are strict zod objects with required nullable fields. Parse a tagged fixture with `planMessageSchema` and narrow on `type`. Build every storage key with `storageKey` from `chat/storage.ts`, never a literal prefix. Read `subscribe` and `send` from the `planSocketAtom` handle.
- **Server text is untrusted.** Render any string a server or the model supplies through `<Untrusted>` (`chat/visible-controls.ts`), including error lines. Build invisible characters in source and tests with `String.fromCodePoint`, because oxfmt rewrites `U+202E` and `U+200B` escapes into the raw characters. Link targets built from server ids go through `summaryLink`.
- **Lazy boundary and test tooling.** No `@codemirror` import outside the lazy loader (`editor/load.test.ts` fails a static one); jest-dom is not installed, so assert with Testing Library queries and plain matchers. `getByRole` takes the name string and no `exact`. Build fixtures from schema exports, not guessed fields. `chat.contracts.test.tsx` imports `node:fs` and `node:path`, which `chat/node-types.d.ts` types by a Node reference; it adds Node globals to the whole browser program, so keep it to those tests.
- **Contract tests.** Stub `window.matchMedia` so `min-width` queries match: below `lg` the panel is a sheet and the complementary region the contracts query does not exist. Seed chat frames as raw `{ type: "chat", frame }` JSON through the `FakeSocket` seam set in `planSocketAtom`. A size-cap test needs multibyte text: a quote is cut at 2,000 characters, so only 37,000 `é` plus 23,000 `a` typed and a 50,000 `é` attachment cross the 100,000-byte cap while the typed text alone stays under it, and the test asserts Send is enabled before the attachment is added.
- **Dialogs and focus.** Radix `DialogContent`'s `onCloseAutoFocus` still runs the default trigger focus under a parent-conditional unmount (`open && <Dialog open>`), from the `FocusScope` cleanup through `setTimeout(0)`; tests `waitFor` the active element. Focus handoff after "New chat" reads `document.activeElement` in a `useLayoutEffect` cleanup of the unmounting child.
- **Test files.** Tests stay under 400 lines; a new test for a file near the limit goes to a sibling (shared harnesses live in `test-kit` files such as `panel-test-kit.tsx`). When a plan replaces a placeholder, update the tests that pinned the placeholder (`concept.contracts`, `concept-route` pinned the disabled "Available once chat is built" offer) in the same change.
- **Gate.** Once subagents have run, the main agent's own full vitest and lint are blocked by the stage guard; run `loom check`.
- **Announcers inside page content use `role="status"`.** `aria-hidden`'s `hideOthers`, which every Radix modal runs, keeps every `[aria-live]` element (even `aria-live="off"`) and all its ancestors exposed, so an `aria-live` span inside the page behind a dialog leaves the page reachable to a screen reader.
- **The pressure dialog states no minute figures.** Its estimated-time line says the time grows with the rounds: no data source for durations exists in the pressure options or the run payload, and an invented figure would mislead.

## New PlanMessage Variants Need Both Schema Arms

A Rust `PlanMessage` variant reaches the browser only when `web/src/plan/api/schema.ts` lists its tag in `PLAN_MESSAGE_TYPES` and `planMessageSchema` spreads the module's message schemas (`summaryMessageSchemas` for the four summary frames). Without the tag the socket drops the frame; without the schema `tests_schema.rs` tag parity fails. The Rust stage that adds the variant checks only Rust round trips, so the web stage owns both edits even when `schema.ts` is outside its Files list. A Rust fixture that serializes an `Option` with ordinary serde writes `null` for an absent value: populate every optional field in the fixture or the web parity test breaks.

## Visual Stages and the Screenshot Script

A plan with a visual target gives its workers one design source. Two procedures have been used; pick per plan.

- **Locked mockup.** The mockup is committed into the brief bundle as structure, CSS values and copy per screen (`doc/plans/feat-planner/briefs/feat-planner-12-ui-repair/`, `common.md` first), because stage sessions cannot open claude.ai ([why](../mistakes/plan-server-delivery.md)). Plan 12 used it, and it passed every gate while the feature screen stayed unusable ([the mistake](../mistakes/planner-ui-repair.md#the-repair-passed-every-gate-while-the-feature-screen-stayed-unusable)).
- **Designer-set `DESIGN.md`.** A designer worker on the fable tier sets `web/src/plan/ui/DESIGN.md` and `ui/design.css` first, with a do-not list; later workers read it, and the plan is accepted by a journey script (`scripts/plan-journeys.sh`, `web/scripts/plan-journeys*.mjs`) that walks user tasks in a real browser, not by structure and copy. Plan 13 used it.

Every worker brief names its design files. Visual and layout stages run on Claude lanes; implementers load `frontend-design:frontend-design` first, and the brief's values and copy win over the skill.

- **`scripts/plan-screens.sh [--worktree-doc] [--themes=<id>,...] <loom-binary> <out-dir> <route>...`** starts a real `loom plan` server on a shallow scratch clone of HEAD's `doc/` (`--worktree-doc` copies the worktree's `doc/` over it), shoots each route with `web/scripts/plan-screens.mjs` at 1440x900 and 390x844 in Ledger and Graphite (or the `--themes` ids: `ledger`, `harbor`, `aubergine`, `graphite`, `midnight`, `obsidian`, `indigo`) and exits non-zero on a console error, a page error, an HTTP status of 400 or more on a route, or a page that never renders `#root`. Run it from the worktree root after `cd web && bun run build` and `cargo build` (the binary embeds `web/dist`). Loopback is per Bash call, so the server and browser run inside the one script. It has no scripted step: opening a run or a dialog needs a throwaway Playwright driver around the same server start, in the same Bash call. A driver under `$LOOM_SCRATCH_DIR` has no `node_modules`, so it imports `playwright-core` by absolute path (`<worktree>/web/node_modules/playwright-core/index.mjs`) and launches with `args: ["--no-sandbox"]`, as `plan-screens.mjs` does. Build from a `git archive` export in scratch when a host gate is reading the live worktree.
- A stage sandbox has no Claude login, so the server answers read-only and session, pressure-dialog, run, done and help views need socket frames patched in the browser (their data is synthetic) or are checked by code and tests only; say which in the review.
- `doc/plans/**/DONE-*` is gitignored, so a worktree or scratch clone has no archived plan sources: `loom plan` there drops every engineering-overview citation (`plan_server/concept/body.rs` `citations()` finds no source) and deletes `doc/loom/summaries/plans/feat-planner-*.md` as deleted-source summaries. Before shooting `/f/<feature>/engineering` from a clone, restore each summary's `of:` path with `git show <deleting-commit>^:<old path>` before the server starts.
- A worker's vitest pass does not prove the bundle builds (a test fixture missing a `lock.plan` field shot a stale bundle, and a fixture typed `as const` passed vitest and failed `tsc -b`, [the mistake](../mistakes/planner-follow-ups-delivery.md#a-test-constant-typed-as-const-passed-vitest-and-failed-tsc--b)): rebuild before shooting.
- A screenshot driver `cd`s into an absolute scratch path in the same command as any `git clone`; a clone left in the worktree root holds a `.git` the sandbox cannot delete ([the mistake](../mistakes/planner-follow-ups-delivery.md#a-screenshot-driver-cloned-into-the-worktree-root)).
- Journeys J2 (needs sealed summaries: `doc/loom/summaries/` is not in the tree), J3 (the `/tmp` plan-lock 500) and J4, J5, J8 (tmux) cannot pass in a stage sandbox; run them outside a stage.
- Compare a visual stage with its mockup frame by frame. A mockup's wide and narrow frames can disagree (starter pills drew glyphs in one and none in the other), so the brief names the winning frame.
- A scroller that holds `position: absolute` content (sr-only text included) is itself positioned. Otherwise that content's containing block lies outside the scroller, so it is never clipped and its overflow scrolls the page: sideways at 390px (`.plan-step-list`), or the whole chat with a long transcript (`.chat-transcript`). Layout overflow is invisible to jsdom; check a long transcript in a real browser.

## UI Repair Test Rules

- **Contract tests are top-level `it()` calls** whose names equal the contract string; a `describe` wrapper breaks `-t` ([the mistake](../mistakes/planner-ui-repair.md#contract-tests-wrapped-in-a-describe-matched-no--t-filter)). A frozen contract file holds contracts only: a passing non-contract test does not belong there.
- **Seed what the contract needs on the wire, not in a mock.** Repair contracts seed a session's owning feature as `session.feature` through the `FakeSocket` seam; with the key removed the strict `sessionViewSchema` rejects the frame and the contract fails with zero cards. Help scenes parse `sessionViewSchema` at module load, so a new required wire key fails every suite that imports the help footer.
- **Tests that mount a full route go through `renderAt`** (`concept/concept-route-support.tsx`), which stubs the wide layout and clears `localStorage`: jsdom answers `matchMedia` false, which moves Settings and the view tabs into the overflow menu, and the desktop chat panel mounts at the same 1024px breakpoint and restores its draft from `localStorage`, so attachments leak between tests without the clear. The stub is not exported, so a test file inlines its own only when it renders outside `renderAt`.
- **Selector contracts of help scenes** (`:scope > h3`, `section[aria-labelledby]`, `aside[aria-label="Taking shape"] > section:nth-of-type(n)`): a stage that restyles a component a scene renders runs that scene's test. Card links are named by the feature slug (`home/feature-card.tsx`).
- **Test-integrity events.** A brief that orders pinned-copy tests rewritten raises one event per test file at completion; keep the base guard assertions that still hold and file one `dispute-integrity` after the commit.
- **Tailwind and CSS layers.** Utilities outrank `@layer components` CSS; a component whose look comes from `DisabledReason` is restyled with `[&_button]:` classes on a wrapper, and a unlayered stylesheet (`settings/settings.css`) outranks the layered utilities of a shared `DialogContent`.
- **Bidi characters in source.** The Edit tool, tool-call strings and Python heredocs decode a typed backslash-u202E into the real character; build it with `String.fromCodePoint` or a doubled backslash, and grep tests you add for the raw character. The Write tool does the same to ` ` and ` ` inside a regex literal, where the raw separator ends the literal and breaks the parse (`vite:oxc PARSE_ERROR`): `rg -c` the file for the raw character after a rewrite and prefer Edit.
- **Journeys.** `scripts/plan-journeys.sh [--strict]` starts a real server on a scratch clone and runs `web/scripts/plan-journeys.mjs` (kit and chat steps in `plan-journeys-kit.mjs`, `plan-journeys-chat.mjs`). A step that judges content measures the routed page, not `main`, and a difference between widths on one route is a defect to chase. No journey script feeds chat frames into the page: `plan-screens.mjs` and the journey scripts add only the theme init script, so a driver that needs a session view stubs `WebSocket` in its own `addInitScript` and replays `web/src/plan/api/fixtures/chat-snapshot.json` frames. J3 (edit and save) fails in a stage sandbox: `/api/save` takes the plan lock under `/tmp/loom-plan-locks-<uid>` (`fs/locking.rs`, `/tmp` outside `cfg(test)`) and `/tmp` is read-only there, so the route answers 500 "Failed to open plan lock"; that is the environment, and an operator runs J3 outside a stage. The activity popover opening on arrival at every route is deliberate (its rebuild prompt opens when summaries are out of date); the kit dismisses it with Escape and prints a NOTE. J4, J5 and J8 need tmux sockets, which a stage sandbox cannot create; they print PENDING there, `--strict` turns PENDING into a non-zero exit, so a stage runs the script without `--strict` and an operator runs the PENDING journeys outside a stage. A subagent cannot run `bun run build`, `cargo build` or `tsc` (the verify guard), so the main agent builds and shoots.
- **Shared chat parts.** A stage that changes `chat/` parts runs the consumers' tests (`help/chat-scene`, `files/doc-heading-view`, `concept/concept-route`) before review: an acceptance run scoped to `src/plan/chat` leaves them to break unseen until the impact step.
- **Press helpers move focus.** `fireEvent.click` does not focus its target. A contract about focus after a click (`open-all-becomes-fold-all`) focuses each header button before clicking (the `press` helper); its focus assertion then rejects a Fold all whose run removal moves focus to the column fallback and accepts a relabelled or remounted button named Open all.
- **Collapsed origin item.** A chat's origin item draws no prompt text until Show is pressed (`items.tsx` `UserItem`); any test that reads its text clicks Show first (`replay.test.tsx` `replayItems` did not).
- **Tests that pin a literal the plan changes.** When a fix would change pinned copy, search the tests for the literal first: `summary-panel.test.tsx` pins "fresh unknown · cache reads unknown · output unknown" and `summary-status.test.tsx` pins "1/3" in `SummaryStatusRow`'s right column while a rebuild runs, so collapsing an all-unknown token line or dropping the count there needs those assertions changed.
- **Impact on guards.** When a guard moves from a class to a CSS selector, pin the attribute and the rule through `?raw`. Before an integrity dispute drops an assertion, name its successor test or the deleted behaviour.

## Planner Review Fixes Test Rules

- **Contracts for code that does not exist yet.** A web contract reaches a not-yet-created atom through a namespace import (`import * as atoms from "@/plan/state/atoms"`) and types it as `ExtractAtomValue<typeof atoms.kickoffDraftsAtom>`: the file loads and fails red at run time until the stage adds the atom, then typechecks. A contract that emulates the browser's Enter in a rename field sends keyDown, then submits the form only when keyDown was not prevented and nothing was sent, so an `onKeyDown` or a form-submit implementation both pass.
- **Mocks in shell contracts.** `shell.test.tsx` and the footer contracts mock `PlanHeader` and the help and settings dialogs, so the footer's quota meters must come from the shell-owned summary feed (`SummaryFeedHost`), never from the header pill. The changes-page contract renders the real routes and header unmocked. The pill's frozen contract tests mount it without a Router, so a control that navigates guards on `useInRouterContext`.
- **Distinct ids in send tests.** `proposal.test`'s `beforeEach` mocks `crypto.randomUUID` to one value, which makes a doubled send fail inside `registerPending` and hide the double; a regression test for a double dispatch uses distinct ids.
- **Feature names.** `isFeatureName` (`new/feature-name.ts`) rejects spaces, so a `/f/<feature>/…` test with an encoded space never reaches a document.
- **Bundle size.** `plan.js` must stay under vite's 500 kB chunk warning; help and edit mode are lazy chunks for that reason ([the shell](../architecture/planner-web-shell.md#header-and-dock), [the editor rules](#live-preview-editor-rules)).
- **Wiring checks match text.** Keep each wired call in code, not a comment ([the mistake](../mistakes/planner-review-fixes.md#a-fix-worker-satisfied-a-text-wiring-check-with-a-comment)).
- **Chat fixtures.** A chat test that sends and then asks for a final write runs the pasted message's turn to Idle first ([the mistake](../mistakes/planner-review-fixes.md#a-chat-test-sent-a-message-and-asked-for-a-final-write-without-finishing-the-turn)).

## Planner Polish Rules

- **Desktop chat in tests.** The panel shows from 1280px (`DESKTOP`, `chat/sheet-state.ts`); `panel-test-kit.tsx` `media()` matches only the 1024px query, so a test that needs the real panel body stubs `matchMedia` true for every `min-width` query.
- **A state word and an item draw different marks.** A test that finds a running or rebuilding mark selects `svg.lucide-refresh-cw.plan-arrow-spinner`; the dot (`.activity-glyph__led`, a span) stands only before an item or action ([the rule](#state-word-marks-and-item-marks)). A roundel sits under an `aria-hidden` ancestor with `busyLabel=""` and `idleLabel=""`, or a second status region and stray text appear ([the glyph](../architecture/planner-web-shell.md#roundel-and-busy-text)).
- **Selection after Add to chat.** The sheet takes focus on a button when it opens, and jsdom parks a collapsed range there: assert `getSelection().toString() === ""`, not `rangeCount === 0`.
- **Chat CSS hooks.** Layout for the run line hangs on `.chat-run-line`, never `.chat-run-header`, which the pressure head shares. A quoted chip label is read from `.chat-chip-open` or `.chat-chip-label` `textContent`, because `getByText` matches an element's own text nodes only.
- **Frozen names win.** A frozen contract's query fixes a name or a layout: the `SummaryPanel` columns repeat their labels (each label within 40 characters of its figure), and the kickoff remove button stays "Remove". Record the cost in concerns rather than renaming.
- **Briefs.** Give a fix worker absolute worktree paths and say never to read the main checkout. A Rust worker that edits a function runs `cargo test --test maintainability` in its single check (the 50-line limit). A visual defect from integration-verify shots goes to a fable worker that loads `frontend-design:frontend-design`, one per area, with the before shot and the real data shape.

## Planner Follow-ups Rules

- **`runOffer(offer, seed)`** (`web/src/plan/offers/actions.ts`) calls `handler(offer)` with one argument when `seed` is undefined: a trailing `undefined` argument breaks `toHaveBeenCalledWith(offer)` in `pace.test.tsx` and `offer-button.test.tsx`.
- **File-mode addresses drop `doc/`.** `reviewHref` of a top-level run review in `doc/plans/` is `/files/plans/<review file>` (`feature/source-href.ts` `toAddress`), while a feature-owned review opens at `/f/<f>/source/plans/<f>/…`; a test that expects `/files/doc/…` is wrong.
- **Stub `matchMedia` exactly.** A stub that answers true to any query containing `reduce` also answers true to `(prefers-reduced-motion: no-preference)`; the count-up then reads as reduced motion. Answer the two queries separately.
- **Reorder `mod` lines as `cargo fmt` does.** A scaffold line a stage text places after `mod tests;` belongs where `reorder_modules` sorts it ([the mistake](../mistakes/planner-follow-ups-delivery.md#the-stage-texts-scaffold-order-disagreed-with-rustfmt)).
- **A frozen contract that names a banned literal** builds it by concatenation, or a plan-level `after_stage` truth check matches the contract itself ([the mistake](../mistakes/planner-follow-ups-delivery.md#a-frozen-contract-named-an-id-that-a-plans-truth-check-bans)).
- **Accent text and error text use their own tokens.** Accent-coloured text runs take `--accent-text` (4.5:1); `--accent-ink` stays for lines and glyphs (3:1). A 12px error figure takes `--tone-blocked` (4.9:1 on the Ledger page), not `--destructive` (3.8:1). Contrast floors: [themes](../architecture/planner-web-shell.md#themes).

## A Change That Deviates From the Product Spec Updates the Spec in the Same Change

When the implementation stops matching `doc/product/<feature>/` (an operator's correction, a design rule rewritten in `web/src/plan/ui/DESIGN.md`, a surface added or removed), the change rewrites the spec's affected sections to the new truth and commits them with the code. A stale spec is a defect, reported nowhere: the next agent builds from it. Before committing, `rg` the spec for every name the change retired (a component, a glyph, a surface) and rewrite each hit.

## Live Preview Editor Rules

The editor's design is in [the live preview editor](../architecture/live-preview-editor.md).

- **Lazy edit mode.** `EditMode` is a `React.lazy` chunk in `reading-column.tsx`; a static import of it grows `plan.js` past 500 kB (504.6 kB before, 412 kB after). A vendor `codeSplitting` group cannot fix it: the lucide and radix code in `plan.js` is shared with `index`, and a source group pulls dependencies recursively. `bundle-rules.json` `plan.html` therefore forbids the chunk `src/plan/editor/edit-mode.tsx` and also the text sentinels `Your kept text` (`edit-panels.tsx`) and `took authoring. Your text is kept as a draft.` (`edit-body.tsx`): `forbidChunks` cannot see a module merged back into `plan.js`, and a static import that skips `EditMode` would tree-shake a sentinel owned by only one of its files. A new editor module with its own user-visible string adds a sentinel.
- **Chunk warning checks.** The dist criterion hides the warning (`--logLevel error`); `cd web && bun run build` prints it. Check the size after a change that grows `src/plan/**`.
- **Browser targets in jsdom.** A browser targets the parent element of the text node under the pointer (`.cm-line` for unstyled text); a test that dispatches on a text node, or on `domAtPos` at the edge of a hidden range, drives a path no browser takes. The Mod-click helper in `live-preview.test.ts` fires on the parent element of the text node holding the clicked character. Read it before briefing a fix that depends on the event target ([the mistake](../mistakes/planner-polish.md#a-dom-target-fix-was-briefed-without-reading-the-test-helper)).
- **Parse-dependent contracts.** jsdom draws about 38 lines and the first parse stops at 3,000 characters: a contract about a decoration far down the document scrolls it into view (`EditorView.scrollIntoView`, no selection change) and calls `forceParsing` first.
- **`erasableSyntaxOnly`.** `tsconfig.app.json` rejects constructor parameter properties (`private readonly x`) in `tsc` while vitest accepts them; widgets declare explicit fields.
- **Link-follow contracts.** `resolveLink` reads a bare word like `notes` as a `doc` link relative to the document, so a contract for "a link that does nothing" uses `javascript:alert(1)` (kind `text`) and `../../../../etc/passwd` (kind `outside`).
- **Commit types.** `loom stage commit` takes `feat`, `fix`, `refactor`, `test`, `docs` or `chore`; a bundle-size fix is `fix` ([the mistake](../mistakes/planner-polish.md#a-commit-used-a-conventional-commits-type-the-rules-do-not-allow)).
- **Browser walk of the editor.** The server is read-only without a Claude login: a stub `claude` on `PATH` that prints `loggedIn:true` enables Edit. Edit is a link (`role` link). The page scrolls in an ancestor outside `.cm-scroller`, so scroll that ancestor; the view is reachable at `.cm-content.cmTile.view`, and `view.dispatch({ effects: view.constructor.scrollIntoView(pos) })` brings a line into view. An `IN_PROGRESS` plan is locked `running`, so the walk edits an unlocked copy. A scratch clone has no `project_key`, so drafts show "browser does not allow storage" and the mode is not remembered. Check both themes (Ledger and Graphite) at 1440x900 and 390x844: the toolbar wraps at 390 without horizontal scroll.
- **Host-job faults.** A vitest run that fails on one suite with a corrupted module read (`ReferenceError: exportc is not defined` in `lucide-react`) or a worker `SIGSEGV` while the file on disk is intact is an infrastructure fault: re-check the one criterion with `--criterion <n>`.

## State word marks and item marks

A mark followed by a state word ("Running", "Drafting", "Rebuilding", "Working", "In progress") is the two rotating arrows: `ArrowSpinner` (lucide `RefreshCw`, two arrows; a single-arrow icon is never used), via `StateMark`, `ActivityTile` for state-word kinds, `PLAN_STATE_WORD_GLYPHS` and `BusyText`. A mark followed by the item or action itself (a named plan, document, pressure test, chat) is the pulsing dot: `ActivityGlyph`, `PLAN_STATE_GLYPHS`. The roundel marks only the header's activity pill and the spine's running plan row. Pick by what follows the mark; `ui/DESIGN.md`, Status, holds the full rule.

## Planning Trace Page Rules

- **CSS order.** A stylesheet that `@import`s another cascades the imported rules first, because an `@import` must precede every other rule. The sheet holding the overrides (media and container width steps) is the one a page imports, and it `@import`s the base sheet; never the reverse. `trace/maps.css` (width steps and the docked focus panel) imports `maps-columns.css` (base); the docked focus panel and the 390px stacking lose to the base rules on equal specificity in the other order.
- **Container queries.** A `@container` query never matches the element that declares `container-type`. Put `container-type` on the parent (the list) and query from the child (`maps-findings.css`).
- **Contrast on dimmed text.** Compute contrast on the composited colour (`alpha*top + (1-alpha)*page` in sRGB), not on the raw tokens. A text run inside a dimmed pill keeps `--foreground` and lets the dot carry the tone: `--muted-foreground` at 55% measured 2.2 to 3.0:1 and at 100% only 4.9:1 on a chip.
- **Adjacent inline parts.** Contract tests match `textContent` with `\b`, so neighbouring chips or list items emit a leading `{" "}` (`second1`, `DiffFirst` fail a `\bsecond\b` match).
- **Settle hash.** `POST /api/settle` takes the opened source document's save hash (`useKeptDoc(path).doc.hash`), never `ConceptPage.file_hash`, which is the summary store's hash.
- **Pinned wording.** A frozen contract can pin words the brief leaves open ("Upstream changed", a dialog saying "My call" with a confirm button named "settle", links named after the document title); the contract writer records them as a decision so the implementer reads them.
- **Size check.** The last step of a web stage runs `wc -l` over every web file the stage touched, tests included (compare with the plan base). A per-stage list misses test files that grew across stages and files outside the stage's own list.
- **Trace pages in a stage.** `loom plan` from PATH runs read-only without a Claude login, so settle, Dismiss and Fold are refused (403 for a curl POST without an `Origin` header matching the server). A fixture for the `revised` state is a well-formed `Settled: <12 hex> stub <12 hex>` line with stale hashes. Headless Chromium blocks `ws://127.0.0.1` with `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS` unless launched with `--disable-features=LocalNetworkAccessChecks`; the Vite dev server answers SPA routes with the dashboard `index.html`, so `page.route` must answer document requests with `/plan.html`. A subagent's Bash hook blocks `bun run build` and `cargo build`; the fallback is the Vite dev server (`bun run dev`, proxying `/api` to a running `loom plan`), which serves source CSS without a build. In a stage sandbox the settle, findings-status and save routes also fail on the read-only `/tmp` plan lock (`fs/locking.rs`).

## Titles and the Reading Face

The reading face (`--font-reading`, serif) is for document text only: a rendered document's body, a summary page's sentences, and verbatim quotations of a document (the scope standfirst's stub words, the Coverage "Why" vision quote, the settle confirm's open-question points, an attached passage in chat). Everything else, including titles, chat prose, finding text, ledes, counts and the spine's head and instruments, is `--font-sans` (Alegreya Sans), or `--font-mono` for ids, slugs and paths; no chrome is italic. Titles are 500 to 600. Sizes and tracking are in `web/src/plan/ui/DESIGN.md`. A brief that names a face by family ("Inter") is checked against the tokens: `web/src/aurora-ui` tokens define `--font-sans` as Inter, but the planner's `web/src/index.css` redefines it as Alegreya Sans, and the screens use the planner token.

## Checking Screens in the User's Browser

The user's browser is Firefox; a Chromium-only pass missed an overflowing spine, leaked chips and misaligned rows ([the mistake](../mistakes/planner-design-brainstorm.md#trace-mockups-showed-every-concept-at-once-and-were-checked-only-in-chrome)). Shoot with `scripts/plan-screens.sh --browser=firefox <loom-binary> <out-dir> <route>...`, at 1440 and 390 in Ledger and Graphite, and compare each shot with the approved screenshot in `doc/plans/mockups/<plan>/`.

- `playwright-core` pins one Firefox build; `plan-screens.mjs` falls back to the newest cached build through `executablePath` when the pinned one is absent. `--browser=` is looked up with `Object.hasOwn`.
- The bootstrap awaits `document.fonts.ready` before the first navigation: an aborted web-font load logs a Firefox console error (`NS_BINDING_ABORTED`) that failed the preflight on about one run in three.
- A walk drives one page. A second browser context is a second viewer and is read-only ("Viewer 1 holds authoring"); switch themes through `localStorage` and a reload.
- Wait for server state by polling from Node (a loop of `page.evaluate(fetch)` until the state matches). `page.waitForFunction(async () => fetch(...))` resolves at once because the predicate's Promise is truthy ([the mistake](../mistakes/planner-design-brainstorm.md#a-walk-driver-waited-on-an-async-predicate)). An edit under `doc/` took about 8.5 s to reach `/api/trace` on the debug binary.
- A subagent cannot produce what it would shoot: the PreToolUse hook blocks `bun run build` and `cargo build` there, and `web/dist` plus the PATH `loom` are built at HEAD. The orchestrator builds web and loom after the look workers return, then shoots.
- Screens a stage sandbox cannot show are said so in the review: a turn footer needs a chat session (tmux socket denied, no Claude login), and Settled writes fail on the `/tmp` plan lock.

## Trace Screen Layout and Test Gotchas

- Tailwind preflight sets `svg { display: block }`, so a bare lucide `<svg>` beside a word inside an inline mark stacks over the word; give it `display: inline-block` or lay the mark out as `inline-grid`.
- `StatusCard` always mounts `.doc-heading-row__detail` (its component may render null), so a `flex-basis: 100%` detail sat between a chip and its action and pushed the buttons to a third line; hide `:empty` details and order them last.
- Contract tests read `textContent` with `\b`, so adjacent block elements and spans need a text separator (a space or punctuation): a settle confirm's counts, a plan's number, an impact row's title and state, a coverage row's Why and How headings (`WhyHow` otherwise).
- Plan detection on a summary page uses the page key's scope (`engineering`), never `plan_state`: a fixture summary has `plan_state` null.
- A redesign that contradicts frozen tests removes or updates them in the main agent and names them in one `loom stage dispute-integrity` filing; the replacement contracts live in `trace/trace-ui.contracts.test.tsx`, and the surviving old contracts keep passing unchanged. Each moved import (`OPEN_DIALOG` to `web/src/lib/open-dialog.ts`) is a one-line edit made where the deleted module was imported.
- Visual edits go through a worker briefed to invoke `frontend-design:frontend-design` first, or the main agent loads it before editing, however small the edit.

## Accessible Names Trim Each Span

The accessible-name and accessible-description algorithms (dom-accessibility-api, used by testing-library's getByRole name/description options) trim each span's own text before joining. A separating space or word placed inside a span is lost: `<span>4</span><span class="sr-only"> headings covered</span>` reads "4headings covered". Put separators (" ", " and ", ", ") in text nodes beside the spans (`feature/spine-instrument.tsx`). The repo has no jest-dom; assert descriptions with `getByRole(role, { name, description })`.

## Dependency upgrade compatibility

The web package uses TypeScript 7 for checking and building. Import-boundary tests in `web/src/plan/editor/load.test.ts` parse TypeScript and JSX with `@babel/parser`; the TypeScript 7 root export has no compiler AST parsing API. Keep AST parsing in these tests so comments, re-exports, import-equals and nested dynamic imports are distinguished.

The reading help scene seeds derived atoms through Jotai 3 internals (`INTERNAL_getBuildingBlocksRev4` and `INTERNAL_KEY_atomStateMap`). Its regression tests must verify every pin target, no live fetch or socket, and no session storage writes whenever Jotai changes.

## Transitive dependency upgrade policy

For web dependency updates, respect the versions and ranges declared by parent dependencies. Do not add overrides or force transitive versions outside those constraints to clear audit findings. Report remaining advisories separately.

## Fake timers around a fetch

A vitest test that fakes only `setTimeout` and `clearTimeout` (`vi.useFakeTimers({ toFake: [...] })`) and waits on a timer that starts after a `fetch` resolves needs two `advanceTimersByTimeAsync` steps inside `act`: a first, shorter one lets the fetch resolve and its body be read with real I/O, which starts the timer; a second passes the timer's delay. One long step runs before the timer exists and the test sees no timeout (`web/src/plan/trace/settle-flow.test.tsx`, "a trace that never catches up releases the button with a notice").
