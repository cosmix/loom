## Codex summary backend

Design and rules: [Summary Backends](../architecture/summary-store.md#summary-backends-claude-and-codex).

- **Never run live.** A stage sandbox has no network and refuses nested `bwrap`, so the sandbox-write behaviour, `check_parent`'s access test and the `O_RDONLY` lock fallback rest on tests and reasoning. Run one real summary job with `plan.summary_backend = "codex"` before relying on it.
- **`loom` on `PATH`.** The job prompt runs a bare `loom plan summary ...`, while hooks use `spec.loom_bin`. A server started from a binary that is not first on `PATH` runs a different `loom` inside the job. Open question: should the spawner prepend the running binary's directory to `PATH`?
- **No in-family model fallback.** `codex_spawner.rs` fails every summary on an account without the chosen model, where pressure falls back (`codex_model_candidates`, `spawn_codex_with_fallback`). The default `gpt-6.1-terra` has no siblings, so only a user-picked model is affected.
- **Guard.** `codex_snapshot` (`guard.rs`) re-implements `config_guard`'s bounded symlink walk with weaker path handling (one walker with a start directory would serve both); the failure text names one instruction file only, though two are guarded, and two tests pin the string.
- **Prompt and config.** `planning/guidance/text/summary_codex.md` tells the job to use the feature name supplied in the assignment, but `render_prompt` supplies ids and the runtime path only. `SummaryModels::load` never returns `Err`, so the `Err` arm in `backend.rs` and its doc sentence are dead.
- **Logs.** `codex-logs/` gets one file per job and is never pruned; the log path shows in the panel only while the job runs, so a failed job keeps just the log's last line.
- **Lifecycle edges.** The registry keeps a job after `wait()` reaped the leader, so `terminate`/`force_later` can signal a reaped group (pgid reuse window); `settle_outcome` reads `stopping` and removes the job under two lock acquisitions; detecting a substituted outcome with `guarded != outcome` is ambiguous when the log tail equals the guard's message; a stop for a session that already left the job map reaches `RealSpawner` and prints a spurious line; `stop` and `stop_all` both SIGTERM and start two kill threads; a job that seals its last id and exits in the 1-2 s before the watcher's batch starts one extra short `codex exec`. A second `TornDown` test would pin its difference from `job_ended`.
- **Duplicated constants.** `CLAIMS_DIR` repeats the private constant in `planning/summary/claims.rs` (export it as `DRAFTS_DIR` is); `lock.rs::write_denied` matches the same errnos as `context::graph_store::is_write_denied`.
- **`safe_fs.rs` seccomp assumption.** A real `EPERM` on an immutable or append-only file sets `OPENAT2_SUPPORT` to 2 for the whole process although the code treats it as seccomp; the portable walk still refuses symlinks, so only the fast path is lost.

## Planning sessions can outlive their server

The owner watch (`plan_session/owner_watch.rs`, [the bridge](../architecture/planning-session-bridge.md#interrupt-end-teardown)) reclaims a session's tmux server 15 minutes after the project's server lock holder went away, so a SIGKILLed server no longer leaves one forever. Measured with a fake `claude` under a scratch home: SIGTERM tears the session and its tmux server down within seconds; a new server on the same project resumes a survivor (`bridge/recovery.rs:143`).

- The watch starts once from `launch/script.rs`. If it is killed, or `watch_target` returns `None`, the session is unwatched for life with nothing logged, and recovery does not restart it.
- `watch_target` reads `session.json` once while `write_record` truncates and rewrites it in place (`fs/safe_fs.rs:341-345`); a read inside that window ends the watch silently. A short retry would close it.
- A failed or timed-out `kill-server` gets one attempt, then the watch returns and the session stays; a bounded retry would change the specified behaviour.
- Teardown does not call `terminate_children`, so `record.children` survive until a later server's recovery.
- No test ran the real watch process under a pty; the `setsid` fix rests on a probe with `script -qc`.
- In-crate tests resolve their home through `test_loom_user_dir` (`planning/runtime.rs`): a per-process `loom-test-home-*` directory made by `tempfile::Builder` (random name, mode 0700), so `cargo test` no longer starts real `claude` sessions under `~/.loom/plan`. The directory sits in a `OnceLock`, is never dropped and so accumulates in the temp directory. A fake `claude` for such a test must answer `auth status` and sleep only on `--session-id`, or the server's own startup probe reads as the session.

## Live preview editor: reviewer suggestions

From the live preview editor plan. None blocks use.

- **Accessibility.** Every task checkbox is named `Task` (`live-preview.ts` `CheckboxWidget`); name it after the item text. In a read-only editor the box is not `disabled`, so it announces itself as operable although a click changes nothing; set `input.disabled` from `state.readOnly` (the editor is rebuilt on a read-only change). Bold, Italic and Link buttons carry no `aria-keyshortcuts`, and a disabled formatting button has `pointer-events-none`, so its `title` never shows and nothing says why (Save uses `DisabledReason`).
- **Help.** `help/shortcuts.tsx` lists Save and Esc for the editor but not Mod-b, Mod-i, Mod-k or Mod-click to follow a link.
- **Failed lazy chunk.** `React.lazy` keeps a rejected import, unlike `loadCodeMirror` (`load.ts`, which clears and retries). A failed `edit-mode.js` fetch throws to the shell `ErrorBoundary` (`plan/shell.tsx`), which resets only on a pathname change, so leaving edit mode (a query change) keeps the error until the reader navigates to another path or reloads. No editor text is lost, since none exists yet. A retrying import factory or a local boundary with Retry fixes it.
- **Anchor links.** Mod-click on a `#anchor` navigates to `toAddress(path, anchor)`, which drops `?edit=1` and leaves edit mode; the reading view scrolls in place. The plan specifies it, so it is a known difference.
- **Command edge cases (`md-commands.ts`).** Heading on a list item yields `# - item` (the list is split; insert after the marker instead). A table inside a quote inserts its rows without the `>` prefix. `codeBlock` repeats only the first line's container prefix on both fences, so a later line with a deeper container (`> > x` after `> y`) leaves the fences shallower; the result is still valid Markdown.
- **`destination()` (`live-preview.ts`).** It unescapes backslashes for every URL node, including autolinks `<http://a\_b>` and bare GFM URLs, where CommonMark processes no escapes, and it decodes no entities such as `&amp;`. Apply unescaping only when the URL's parent is `Link` if it matters.
- **Cleanup.** `LivePreviewOptions` is exported and used only inside `live-preview.ts`. The `loadables` Map in `concept/passage-doc.ts` grows by one entry per path and is never pruned, like `documents` in `passages.ts`; a concern only if paths are unbounded.

## Live preview editor: merge view rewrites CRLF files

The merge view (`codemirror.ts` `createMergeView`, used for a conflict or an older draft) has no line-separator handling: the plan left merge and diff views unchanged. An edit in the merge view of a CRLF file reports LF text, so the save rewrites every line ending. The source editor keeps CRLF through `detectLineBreak` and `EditorState.lineSeparator`. The behaviour predates the editor plan.
