# State Confinement Gaps

> Open confinement gaps: caches, task outputs, macOS networking, stage cache

## Open Gap

This risk is accepted and stays open; no plan addresses it:

- **Shared package caches** stay session-writable and are executed by the operator's own builds.
  Every capsule's `allowWrite` carries `sandbox/package_caches.rs::PACKAGE_MANAGER_CACHE_WRITE_PATHS`:
  cargo's `registry`, `git` and lock files, rustup's `downloads`, `tmp` and `update-hashes`, and the
  bun, npm, pnpm, yarn, deno, uv, pip and go caches. Cargo does not re-verify extracted sources, so
  an edited `build.rs` under `~/.cargo/registry/src/<registry>/<crate>-<version>/` runs at the
  operator's next host build of any project using that crate; the same holds for any cache a host
  tool reads without re-hashing it (the go build cache, uv's `archive-v0`). A full copy per
  session is not an option: on the machine where this was measured the cargo registry held
  1.75 GB, bun 30 GB, npm 7.7 GB and uv 62 GB, and ext4 has no reflinks.

## Task Output Files Are Session-Writable

Sandboxed commands can rewrite `/tmp/claude-<uid>/<project>/<session>/tasks/<id>.output`, including another session's. `models/forward_receipt/locator.rs::validate_task_output_path` checks layout, owner and size, none of which tells a host-written file from a rewritten one, so a session can forge the forwarding evidence read from these files. A deny cannot close this: the directory is Claude Code's `TMPDIR`, its Bash wrapper must write there, and Linux skips `denyWrite` globs ([why the deny failed](../mistakes/sandbox-protected-hooks-dir.md#denying-claude-codes-tmpdir-fails-every-sandboxed-bash-call)). Closing it needs reader-side evidence that a session cannot write. `sandbox/control_surfaces/session_denies.rs::session_denies` therefore leaves `<tmp>/claude-<uid>` writable, because a deny on that root would fail every sandboxed command. Direction: protect the receipt channels by a path the sandbox can express (a fixed directory outside `TMPDIR`) and add a canary that a sandboxed Bash call returns the command's own exit code.

## macOS Confined IP Networking Is Off by Default

A confined command on macOS gets no IP bind, listen, connect or send (`NetworkAccess::Denied`, `verify/criteria/confine_seatbelt.rs::profile`); Unix sockets follow the path rules. A plan or stage opts in with `sandbox.network.allow_local_binding: true` (a stage's own `network` section replaces the plan's whole, as `sandbox::merge_config` merges it; the field needs no author acknowledgement). `verify::criteria::stage_network` turns it into `NetworkAccess::Loopback` for criteria and impact-test runs (`CriteriaConfig::plan_local_binding`, read from the plan snapshot by `plan_local_binding`) and for contract runs (completion, and the freeze red run in `host_verify/freeze.rs`). Linux is unchanged: bubblewrap gives each command a private network namespace with its own loopback, and `allow_local_binding` there only widens the Claude Code session sandbox (`sandbox/settings/policy.rs`).

Residual of the opt-in, measured on macOS 27.2.1 with real `sandbox-exec`: Seatbelt cannot hold a bind to loopback. `localhost` in a `local` filter matches every local address and `"127.0.0.1:*"` is a parse error, so a command can bind `0.0.0.0` or a LAN address and a LAN peer can reach the listener. The outbound `localhost:*` grant reaches every host loopback listener (the loom dashboard on 7373, databases, dev servers), and a command can take a port a host client expects. A connect off the host stays denied. A `(deny network-outbound (remote tcp "localhost:4226"))` after the grant keeps a host sccache server, which runs compilers outside the boundary, unreachable on macOS 26.7 and 27.2.1; it holds only because the grant is spelled as separate `tcp` and `udp` rules (next section).

Without the opt-in a listen test fails on macOS, and it keeps failing. `verify/environment.rs::sandbox_denial` marks `EPERM` and "operation not permitted" (Node and Python print them), but not bun's `EADDRINUSE` or `FailedToOpenSocket` for a refused bind: `EADDRINUSE` is also a real failure text, so marking either would turn a real port clash into an environment note. Instead a run that failed (non-zero exit, not timed out) and was confined on macOS without loopback, and whose output holds either code as a token on a line (case-insensitive, `stderr` before `stdout`), carries one note from `environment.rs::bind_refusal_hint`, starting `refused bind?`. The note quotes the first matching line and names `sandbox.network.allow_local_binding: true` in the plan or stage, which an operator sets, and the dispute route for a run that fails only because of where completion runs. `refused_bind_note` applies the gate; `loopback_refused` on the run result is set in `verify/criteria/runner.rs::run_criterion` from `refuses_loopback` (macOS, `CommandConfinement::Confined`, `NetworkAccess::Denied`), the one set-site for acceptance criteria, impact-selected tests and the completion contract check (the last two through `probe.rs::CriteriaProbe::run`). The note is independent of the denial note, so an output holding both prints both. Runs that go through `executor.rs::run_spec_in_stage_network` keep `loopback_refused = false` and get no note: the contract freeze's red run, dry-run, `after_stage` and wiring commands, and the goal-backward truth and dead-code checks. `loom plan verify --dry-run` renders through `commands/plan/verify/dry_run_classify.rs` and shows no note. The remedy for a stage that serves and dials on loopback is the opt-in.

## Where the Loopback Grant and Its Residual Are Pinned

`confine_seatbelt.rs::LOOPBACK_NETWORK` allows `network-bind` and `network-inbound` on `(local ip "localhost:*")` and outbound as two rules, `(remote tcp "localhost:*")` then `(remote udp "localhost:*")`; `SCCACHE_PORT_DENY`, `(deny network-outbound (remote tcp "localhost:4226"))`, follows them and refuses a host sccache on port 4226 (the last matching rule wins). The split is required: measured with real `sandbox-exec`, after a single `(remote ip "localhost:*")` allow no port deny in any spelling or order holds on macOS 26.7 (the `macos-26-arm64` CI image), while after the tcp/udp pair the tcp deny holds on 26.7 and 27.2.1, over IPv4 and IPv6. `require-not` inside a network allow is ignored on both. See `mistakes/native-macos-delivery.md#seatbelt-port-deny-ignored-after-a-remote-ip-grant-on-macos-26`. The measured residual is pinned by `confine_seatbelt_network_tests.rs` (cfg(test) only, so the any-host profile tests run on Linux too): a local `ip` filter matches every local address alike, so `localhost:*` equals `*:*` and wildcard and LAN binds are admitted; `network-inbound` sees no peer, so a bind, listen or receive cannot be held to loopback; a remote `localhost:*` admits every address configured on the host (LAN IPs, `lo0` aliases) but not `127.0.0.2`. `confine_provision_tests.rs` (macOS-gated) calls `provision_network_rules(&grants)` directly, so changing that signature breaks compilation outside the Seatbelt files. A confined listener can take a port a host client expects (an OAuth callback) and answer unconfined host clients.

## Open Reviewer Suggestions From the Stage Cache Plan

None of these blocked a stage; each names the file and what to change.

- **Provisioning keeps a blanket outbound allow.** `verify/criteria/confine_seatbelt.rs::provision_network_rules` allows `network-outbound` and denies Unix-socket connects under two prefixes (the stage-cache base and the session scratch base). The Docker, ssh-agent and loom daemon sockets and the operator's TCP sccache on `127.0.0.1:4226` stay reachable from a provisioning command. Allowing `(remote ip)` plus the `mDNSResponder` literal would close it. No test drives the connection: `confine_provision_tests.rs` only parses the rules; a macOS CI test that a connect to `<stage-cache>/x.sock` is denied and `h.sock` allowed is missing.
- **A stage-cache resolution error skips the before-stage checks.** `orchestrator/core/stage_preflight.rs` (`run_before_stage_checks`) makes the whole gate error when `stage_cache_for` fails, and the caller passes that error as advisory, so the checks never run.
- **A credential-bearing `GOPROXY` sits in the daemon's environment.** `daemon/server/environment.rs` keeps `GOPROXY` for the cache, so `Inherit` commands and the tmux server inherit it; filtering userinfo at capture would remove it.
- **`goproxy_has_userinfo` misreads a scheme-less entry.** It decides scheme-ness by `://` anywhere in the entry, so `user@host/a://b` passes. Testing for `://` before the first `/` would close it. The input is the operator's own environment, so the risk is low.
- **A process that already carries the stage environment resolves a nested root.** A session exports `XDG_CACHE_HOME=<root>/xdg`; `StageCache::resolve_from_process` called inside it (`verify/criteria/confine.rs`, `stage_cache/cleanup.rs`) would resolve `<root>/xdg/loom/stage-cache/<hash>`. The relay avoids it today; a guard or a comment would keep it so.
- **Duplicated helpers.** `stage_cache/roots.rs::push_unique` copies private helpers (`sandbox/control_surfaces.rs` has a generic one) and `HomeGuard` in `verify/criteria/confine_stage_cache_tests.rs` copies the one in `stage_cache/contract_tests.rs`.
- **Hard failure when `HOME` is unset.** Confined acceptance, provisioning and the other callers of `confined_stage_cache` fail without `HOME`. `Inherit` stages skip the cache, so only a confined stage under a daemon with no `HOME` is affected.
- **The worker locates its invocation directory by layout.** `native_worker/supervisor/mod.rs` uses `dir.ancestors().nth(3)`, which hard-codes `store::invocation_dir`'s depth; `LOOM_WORK_DIR` (set in `runner.rs`) or an inverse helper in `store.rs` would not.
- **`ensure()` runs twice for a Linux worker.** `native_worker/supervisor/mod.rs` ensures the root and `native_worker/boundary/linux.rs` ensures it again.
- **The no-follow removal depth is fixed.** `fs/no_follow_tree.rs::MAX_DEPTH` is 64, so an unusually deep `go-mod` or `node_modules` tree fails with `ELOOP` and the root leaks, with a warning.
- **The macOS session `PATH` is the daemon's.** `stage_cache/session.rs` exports the developer directories ahead of the host `PATH`, which is the daemon's; a daemon started with a minimal `PATH` strips tools from sessions that used to inherit the terminal's.
- **An unconfirmed cleanup assertion.** `git/cleanup/tests_stage_cache.rs` asserts an empty warnings list for a plain merged worktree; it was written without a run and needs confirming on the first test run.
- **A comment still narrates history.** `stage_cache/session_contract_tests.rs` says a grant "must no longer be granted"; a current-state sentence would do.

## A Host-Job Test Fails Only Inside the Completion Run

`host_verify::tests_wait::a_terminal_outcome_leaves_a_newer_request_the_other_waiter_wrote` (`host_verify/tests_wait.rs:375`) failed deterministically (2 of 2 runs, in a 647 s suite) inside the completion host job and passes alone in 1.2 s. The stage that met it changed neither the test nor the wait code. Cause unknown; run it alone first, and if it fails only in the full run, suspect suite timing or a shared-state interaction with a neighbouring test before touching the wait code.

## Confined Gradle on macOS Needs the Loopback Opt-In

Under Seatbelt a confined Gradle build needs IP networking even in-process (`GRADLE_OPTS=-Xmx1g`, `stage_cache/environment.rs::GRADLE_IN_PROCESS_OPTS`): every cache lock binds a UDP socket on the wildcard address (Gradle 8.10.2 `FileLockCommunicator.java:48`, unconditional), and the compiler and test workers connect back over loopback TCP. A confined command has no IP networking by default, so the build fails. A plan or stage that sets `sandbox.network.allow_local_binding: true` grants this host's loopback (`confine_seatbelt.rs::LOOPBACK_NETWORK`; residual in `concerns/state-confinement-gaps.md`), which covers the wildcard UDP bind, the loopback UDP pings and the worker connects. That is the expected way to run Gradle confined on macOS; no Gradle build has run under it here, and the Gradle probe (`stage_cache::toolchain_tests::jvm::gradle_resolves_from_the_read_only_cache_offline`) is Linux-only. Loopback TCP and UDP connects under the grant are measured on macOS 26.7 (the `macos-26-arm64` CI image) and 27.2.1; a Gradle build under it is not.

## The Base Comparison's Cache Path Can Exceed `sun_path`

Under a default macOS `TMPDIR` the scratch cache's `h.sock` path is about 133 bytes, past the 104-byte limit, so `stage_cache/environment.rs` omits `SCCACHE_SERVER_UDS` and a confined base run with an inherited `RUSTC_WRAPPER=sccache` would fall back to TCP, which a denied profile refuses. `StageCache::resolve` fixes the `loom/stage-cache/<24 hex>` layout, so the fix is a short-root `StageCache` constructor in `stage_cache/mod.rs` (about 91 bytes with `<scratch>/c`); the at-base job keeps short paths deliberately (`stage_cache/base_checkout.rs`). Revisit when impact base runs fail under sccache.

## Refused-Bind Note: Kernel Run Pending and Open Reviewer Suggestions

No stage can run the macOS kernel check for the refused-bind note: the host job is confined and nested `sandbox-exec` is refused. Operator step after merge, in an unconfined macOS shell: `cargo test --lib bind_refusal` from `loom/` (three tests in `verify/criteria/probe.rs`, none `#[ignore]`; the denied-run test returns early only when `refused_run` errors, the kernel test guards through `sandbox_probe::skip_unless`), then, with bun installed, a scratch plan whose stage acceptance is `bun -e 'const s = Bun.serve({port: 0, fetch() { return new Response("") }}); s.stop(true)'` with `timeout_secs: 30` and no `sandbox.network.allow_local_binding`. Its `loom stage complete` output must show the `refused bind?` line.

Reviewer suggestions left unimplemented, none a defect:

- `environment.rs::bind_refusal_hint` quotes the matched line unstripped, so a lone `\r` or an ANSI escape in the run's output can rewrite the note line; `models/dispute.rs::strip_control(line, &[])` would harden it. The denial note and gate excerpts are unstripped too.
- `impact_tests/report.rs::kept_hints` has no observable effect: `failure_message` looks hints up by kept failures' ids and takes the first match, and `failure_id` is unique per (adapter, package) group. The stage description asked for the filter.
- An output holding both a denial marker and a bind code renders both notes, each with dispute advice (`criteria/output.rs`); this is the plan's "independent of the denial note" decision.
- `probe.rs`: `refused_run` swallows probe errors with `.ok()`, so the denied-run test returns silently where confined commands cannot start, and the `Inherit` case skips on an error although an `Inherit` run needs no launcher. Report the skip through `skip_unless` and `expect()` the `Inherit` run.
- `impact_tests/runs.rs`: `base.rs::at_base` reuses the judge, so a failing base run computes a bind note it drops; one wasted gated scan per failing selection.
- `environment.rs`: the two bind markers are ASCII, so byte-wise case-insensitive matching would avoid one `to_lowercase` allocation per line on a large failing output (same cost as `sandbox_denial`); the first-marked-line scan repeats `sandbox_denial`'s predicate shape and could share a private `first_marked_line(lines, markers)`; the finished-and-failed gate repeats `output.rs::environment_note`'s; the module doc should name the refused-bind hint, whose markers are deliberately not environment markers.
- `runs_tests.rs`: the local `finished` helper only forwards to `ProbeRun::finished`; inline it.
