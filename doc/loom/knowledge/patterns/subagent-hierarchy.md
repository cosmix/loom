# Subagent Hierarchy

> Flat fan-out vs 2-level coordinator hierarchy vs agent teams: when to use each, model mix, file exclusivity.

## Subagent Hierarchy + Ultracode Guidance (2026-06-12)

Loom teaches a 2-level subagent hierarchy (main agent → coordinator subagents → worker subagents) for large well-defined fan-out, and a per-stage `ultracode: bool` flag that licenses Workflow orchestration. The guidance is mirrored across multiple surfaces that MUST stay consistent.

**Capability facts:**

- Nested subagents are supported since Claude Code 2.1.172 (changelog: "Sub-agents can now spawn their own sub-agents (up to 5 levels deep)"); empirically confirmed 2026-06-12 on 2.1.175 (a subagent spawned a nested Explore agent, no flags needed). On older versions the Task tool is simply absent one level down; the coordinator does the work itself.
- The platform allows 5 levels; **loom caps trees at 2 by policy** (auditable file-exclusivity, bounded cost/failure blast radius), enforced via the WORKER PREAMBLE prose, not code.
- The `tools:` frontmatter in `agents/*.md` governs capability: `loom-software-engineer` and `loom-senior-software-engineer` list `Task` (can coordinate); `loom-code-reviewer` does not (always a leaf).
- **Model-inheritance trap:** a nested worker spawned WITHOUT an agent type defaults to the MAIN session model — on an `opus` stage that silently makes every worker opus. Hence "spawn workers BY AGENT TYPE" on every surface.
- **Ultracode licensing:** Claude Code's Workflow tool requires explicit opt-in; the documented trigger is the literal keyword `ultracode` in the session's prompt. Loom controls every spawned session's initial prompt, so `stage.ultracode` injects the keyword at spawn (`orchestrator/terminal/native/mod.rs`, `SessionType::Stage` prompt arm).
- **Ultracode fan-out is Claude-only.** The Workflow tool can only spawn Claude subagents — the codex lane (`gpt-5.6-terra` / `gpt-5.6-luna`) is not addressable from a Workflow script. On a stage licensed for both `ultracode` and codex, codex-tier work goes through normal `loom-codex-forwarder` Agent spawns outside the Workflow, never through the Workflow itself (the "## Ultracode Mode" block in `format/sections.rs` states this).
- **Plan-authoring preference:** one ultracode stage is preferred over three or more parallel sibling stages performing the same operation across disjoint file sets — fewer worktrees, fewer merges. The tradeoff is cost, roughly 15x the tokens of a single session with up to ~16 agents concurrent; full guidance lives in `/loom-plan-writer`.
- **The codex lane is a worker substitution, not a new level, and it splits into two tiers.** On stages listing codex in `implementers`, routine implementation may go through the `loom-codex-forwarder` shim to GPT-5.6 Terra (common implementation, integration tests) or GPT-5.6 Luna (boilerplate, scaffolding, simple unit tests), both at `xhigh` effort, instead of sonnet `loom-software-engineer`. It does NOT replace opus for mainstream architecture/algorithm work, fable for major bugs/visual-UI-design/extremely challenging algorithmic design (no agent type pins fable — the model override is explicit at spawn), or `loom-advisor` for debugging. It is foreground-only (background fan-out is forbidden — [Codex Concurrency](../architecture/codex-concurrency.md)), and it never verifies: verification stays with the opus orchestrator.
- **The codex lane also requires the codex CLI and plugin to actually be installed**, independent of stage licensing. `loom run` preflights this at startup (`codex_lane_status()` / memoized `codex_lane_available()` in `loom/src/codex.rs`, mirroring the Remote Control capability/preflight/resolve shape) and prints an advisory warning — never a hard failure — when the CLI or the plugin's companion runtime (`~/.claude/plugins/cache/openai-codex/codex/*/scripts/codex-companion.mjs`) is missing. When unavailable, the stage signal's `## Codex Implementers` section switches to a fallback note: route terra-/luna-tier work to sonnet, and do not spawn `loom-codex-forwarder`.
- **Lanes are a PER-SUBAGENT choice, not a per-stage mode.** `implementers` is a list of licensed lanes; listing one makes it available, not mandatory. One stage — and one fan-out wave — may hold codex and sonnet workers side by side. File exclusivity is enforced ACROSS lanes: a codex worker and a sonnet worker writing one file is lost work exactly as two same-lane workers would be, so keep ONE file-ownership table covering every worker in every lane, with each row's lane noted.
- **Bounded waits (2026-08-07).** A subagent that has gone quiet is indistinguishable from one that is working, so no watcher or poll may be open-ended: 300s is the ceiling for any single check, re-armed as needed, and the check must terminate on BOTH the success and deadline branches. Per-stage `subagent_timeout_secs` sets the budget the monitor uses; the resulting "appears hung" warning is advisory only ([concerns.md](../concerns.md)).

**Pinning tests:** `cache.rs::test_generate_stable_prefix_contains_required_sections` (hierarchy asserts), `tests_cache.rs::test_signal_contains_delegation_choices_three_way` (incl. negative assert on the old `## Agent Teams` header), `tests_cache.rs::test_signal_ultracode_section_gated`, `tests_cache.rs::test_signal_codex_implementers_section_gated` and `test_recovery_signal_carries_codex_implementers_section` — both now assert the MIXED case (codex licensed but not preferred) still gets the doctrine, on the normal and recovery paths — `tests_doctrine.rs::block_a_agrees_across_every_surface` / `block_b_agrees_across_every_surface`, `plan/schema/tests/ultracode_tests.rs` and `implementer_tests.rs` (parse/default/order/empty/duplicate/advisory), `commands/init/tests.rs` (definition→stage propagation incl. preference order), `tests/integration/implementer_defaults.rs` (plan + stage-file defaults and mixed round-trip).

**Gated-section trap:** a gated section's test is a NEGATIVE assert on its exact header (e.g. `!content.contains("## Codex Implementers")`). Any pointer to that section written into the ALWAYS-emitted stable prefix must therefore NOT spell the header with its `##` marks, or the negative assert can never pass.
