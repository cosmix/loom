# Owned Waits

> Worker-set waits: lease/engine, exit codes

## Owned Subagent Waits (`loom subagents wait`/`watch`, 2026-09-13)

> One bound wait per parent session, keyed to an explicit worker set, replacing a bare-timeout background poll.

**Module:** `loom/src/commands/subagents/wait/` — `lease.rs` (one lease per parent session, dirfd-anchored `fs::safe_fs` primitives, reuses `safe_fs::flock_exclusive` (widened to `pub(crate)`) rather than a second lock implementation), `lease_fs.rs` (owner/mode checks on pre-existing scratch dirs), `engine.rs` (the poll/settle loop), `stall.rs` (hung-worker rules, 2026-09-14), `identity.rs` (`--worker claude:<agent-id>` / `--worker codex:<unit-id>` parsing), `codex_binding.rs` (the wait-only Codex binding, reusing `codex_lifecycle::ledger` readers widened to `pub(crate)` instead of a second JSONL parser), `model.rs`, `output.rs`, `mod.rs` (CLI wiring). Companion job liveness and log freshness live in `loom/src/codex_lifecycle/progress.rs`.

**Contract:** `loom subagents watch --worker claude:<agent-id> --worker codex:<unit-id> [--session <parent-uuid>] [--stall-secs <n>] --timeout <secs>` binds that worker set once, holds one lease for the calling parent session, prints one initial and one terminal record, then exits. It requires `LOOM_STAGE_ID`/`LOOM_SESSION_ID`/`LOOM_WORK_DIR`, so it cannot be used from an interactive session outside a stage (exit 5 `LOOM_STAGE_ID is required`). The bare `--timeout <secs>`-only form with no `--worker` is REJECTED. Exit codes: `0` every bound worker has fresh correlated success evidence; `2` the wait deadline passed (NOT proof any worker died); `3` a bound worker failed or was cancelled; `4` a wait for this parent session already exists (`AlreadyWaiting` same set, `Busy` different set — only one lease per parent session); `5` worker identity or terminal evidence is unknown (never success); `6` a bound worker is hung (`WorkerOutcome::Stalled`, `EXIT_STALLED`). `list`/`harvest` stay one-shot diagnostics, never a wait substitute.

**Hung detection (2026-09-14, `stall.rs`, `progress.rs`):** before this, a worker stayed `Active` until the deadline whatever happened to it — a codex job that died at `status: running` held a `--timeout 3600` watch for 43 minutes ([mistakes](../mistakes/subagent-orchestration.md)). The budget is `--stall-secs`, else the stage's `subagent_timeout_secs`, else 600 s (`DEFAULT_STALL_SECS`; the session heartbeat's 300 s is too short for a thinking turn). Claude worker rules, from the transcript's last-entry timestamp via `classify::analyze_with_evidence_at_ceiling`: `Done` idle > budget (turn ended, no SubagentStop record); `Generating` idle > budget; `ToolWait` on `Agent`/`Task` never (nested spawns have no cap); `ToolWait` on `Bash` only past `max(budget, 1800 s)` — 19,007 measured Bash tool-waits included 71 past 600 s and one of 1,298 s, since a call held at a permission prompt has not started and the tool's 600 s cap does not bind it; `ToolWait` on any other tool idle > budget (the longest measured was a 121 s `WebFetch`). Companion codex rules, only while the record says `running`: `pid` gone (`kill(pid, 0)` ESRCH, or zombie) is `Failed` — definitive, the job cannot complete; newest of log mtime / `updatedAt` / `startedAt` / `createdAt` older than the budget is `Stalled`; `queued` is running. Only signal 0 is ever sent from Rust; the wrapper's cancel owns killing. Failed/Cancelled outrank Stalled; Stalled outranks all-succeeded. On 6 the orchestrator `TaskStop`s the Claude worker (a cancelled codex job needs nothing) and re-delegates the remainder in a smaller brief. Per-poll cost: the companion check runs `locate_job` a second time each 2 s poll (~100 job files); accepted.

**Heartbeat progress/observation split:** the same stage introduced `progress_at`/`activity_kind` on the heartbeat JSON so that repeated `subagents list`/`watch`/`harvest` polling no longer resets the hung-detection clock — see [Monitoring Patterns](../patterns/orchestrator-daemon-loop.md#monitoring-patterns).

**Codex identity contract (worker-evidence W2):** the `PreToolUse` `codex-forward-guard.sh` mints `invocation_id` (`inv-<32 hex>`) and derives `unit_id` (`--unit-id` or `fwd-<forwarder agent id>`), appends a v2 authorization row to `subagents/<stage>/codex.jsonl`, and injects `--unit-id U --invocation-id I` through PreToolUse `updatedInput`; the wrapper exports `CODEX_COMPANION_SESSION_ID=loom.v1:<stage>:<loom session>:<unit>:<invocation>` (`:` is outside the safe-id charset, so the encoding is unambiguous) and `CLAUDE_PLUGIN_DATA=$HOME/.codex/plugin-data`; companion v1.0.6 copies that session id verbatim into `job.sessionId`. The daemon joins a companion job to its authorization row by exact decoded `sessionId` — never by time or "newest job" (never-mtime-as-identity) — and appends `CodexCompanion` Authorization+Observation records via `subagent_lifecycle::store::append_locked`. Unit ids must match `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` (leading alphanumeric — a leading `-` reads as a flag in the wrapper argv, a leading `.` carries path meaning); the guard also blocks a forwarder call outside an active loom stage (`LOOM_STAGE_ID`/`LOOM_SESSION_ID`/`LOOM_WORK_DIR` all set and safe), since outside a stage the wrapper cannot encode `CODEX_COMPANION_SESSION_ID` and no daemon reconciles.

**Codex forwarder unit deadline (2026-09-14; supersedes the "job-survival limit" reading):** inside the Linux stage sandbox a companion job does not outlive its forwarder — jobs were observed dying silently ~535 s after start, exactly when the wrapper's 540000 ms status wait returned. The wrapper used to hand such a job off (`state: active`, "continues under daemon ownership", exit 0), leaving an orphan the watch could not distinguish from a live job. Now `loom-hooks/codex-forward.sh` cancels a job still running at the deadline (`codex-companion.mjs cancel <job> --json`, which interrupts the turn and kills the process tree), prints `LOOM-FORWARD-END {"v":1,"backend":"companion","job_id":..,"outcome":"timed_out","exit_code":124}` and `state: timed_out`, and exits 124; `ForwardState::TimedOut` (serialized `timed_out`) is terminal. The direct lane's supervisor (`_codex-direct.py`) already killed at 540 s and returns `cancelled`/124. **Prevention:** size every codex unit for the deadline — ONE file, or one file plus its test, at most three numbered steps, interfaces pinned verbatim in the brief (one module pair at xhigh measured 24-30 minutes). A timed-out unit is never re-forwarded as is: re-split the remainder against the partial tree; a single retry keeps the same unit id, a split gives each part its own id.

**Codex unit verification limit:** `/tmp/loom-loop-checks` (and the stage TMPDIR generally) is mounted READ-ONLY inside the codex companion sandbox, so any test a codex unit runs against stage fixtures fails at setup before exercising code. Never ask a codex unit to run fixture-backed tests for its own acceptance; at most a compile-only check (`cargo check`/`cargo test --no-run`) — the orchestrator runs the unit's real module tests immediately afterward. A compile-only check cannot catch a behavioral regression (e.g. a swapped-out test fixture helper that silently changes what state a test observes) — the orchestrator's post-unit test run is what catches those, so run it right after every codex unit, not batched at the end.

## Never Pipe a Background `loom subagents watch`/`wait` Through `tail`

A background `loom subagents watch --worker ... | tail -20` "completes" immediately with exit 0 even while workers are still running, because the pipe's exit status is `tail`'s, not `watch`'s — a stale, unversioned PATH `loom` binary lacking a new flag (e.g. `--worker`) also fails with "unexpected argument" that a `tail`-piped background call then silently swallows. **Prevention:** never pipe a background wait through `tail` or any other command; run it bare through `run_in_background` so its own exit code reaches the harness, and check `loom subagents watch --help` against the actual PATH binary (not `loom/target/debug/loom`) before relying on a new flag — an installed binary can lag the worktree's own tree.

## Known limitation: the deadline race window (2026-09-14)

`codex-forward.sh` reports `timed_out` whenever the 540000 ms `status --wait` returns with the job still `queued`/`running`; it does not re-check whether the job completed in the instant between that return and its bounded `cancel` call. A job finishing inside that window is reported timed out and cancelled, though its edits stay in the tree. Deliberate: closing it needs a second non-wait `status` call, which every test stub (`loom-hooks/tests/codex-forward-wrapper.sh`, `loom/tests/codex_evidence/fake_companion.rs`) pins against. The re-split guidance remains correct at that boundary.

`loom knowledge update`/`replace-section` resolve `doc/loom/knowledge/` from the shell's working directory: run from `loom/` they scaffold a second tree under `loom/doc/` and write there. Run them from the repository root.

**Named-agent spawns break `watch`'s id parsing (2026-09-16):** when an `Agent` spawn passes a
`name`, the Agent tool returns an id of the form `name@session-<8hex>`. `loom subagents watch`
rejects it: `WorkerSpec::from_str` calls `forward_receipt::is_safe_id`, which disallows `@`, so the
watch exits 5 ("worker id is empty or unsafe") before binding anything — even though the same spawn
reports success via the harness's own task notification. Spawn Claude workers you intend to watch
without a `name`, or bind the watch on the session id form the tool actually returns.

**A companion liveness check can false-positive across the forwarder's sandbox PID namespace
(2026-09-16):** `loom subagents watch` exited 3 claiming a codex companion job's process was "gone
while its record says running" only 118 s after the forward started. The low PID reported points at
the forwarder's own sandbox PID namespace being invisible to the watcher process — `kill(pid, 0)`
resolves against the wrong namespace. Treat that exit as unverified and wait for the forwarder's own
`LOOM-FORWARD-END` report before concluding the job failed. Separately, a watch naming only `codex:`
workers exits 5 ("worker set does not resolve to one Claude parent UUID") — always include the
forwarder's own `claude:<agent-id>` in the `--worker` set alongside the codex unit id.
