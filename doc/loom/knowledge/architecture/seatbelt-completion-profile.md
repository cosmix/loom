# Seatbelt Completion Profile

> macOS completion Seatbelt profile: pure builder, shared file rules, residuals

## The macOS Completion Profile (Seatbelt) and Its Shared Builders

`verify/criteria/confine_seatbelt.rs::profile` renders the completion boundary as a pure function, compiled on macOS and on Linux test builds, so its policy contracts run on Linux too; `platform_command` only adds the launcher check, and only macOS applies the profile. Off macOS the protected-path rules refuse instead of rendering and no host Cargo home is named, because `confine_protected.rs` and `confine_scratch.rs` gate those helpers to macOS. The file rules for single host files outside the tree live in `confine_ancestors.rs` (the directories above the tree listable, each ancestor's Cargo files hidden by name, `package.json` readable for Node's package-scope lookup) and `confine_seatbelt_files.rs` (Cargo and Maven secrets hidden, Cargo's state files and the per-user Git ignore and attributes files readable); the native worker's profile reuses them through `native_worker/boundary/seatbelt_host_files.rs` ([macOS Boundary](native-codex-workers.md#macos-boundary-seatbelt)), and `quote`/`quote_checked` (SBPL quoting that refuses a control character) are the native profile's. `quote_checked` validates only the listed paths and its closure unwraps for any other path the rule builders pass; today those are ancestors of checked paths.

Network: `NetworkAccess` (`confine_host.rs`, re-exported from `verify/criteria/mod.rs`) grants loopback only on the `allow_local_binding` opt-in, never by default ([Seatbelt loopback grant](../mistakes/seatbelt-loopback-grant.md)). Provisioning keeps a blanket outbound allow but denies Unix-socket connects below the real stage-cache and stage-base bases (`process_cache_bases`); the residuals of the loopback grant are in [macOS confined networking](../concerns/macos-confined-networking.md) and [sandbox gaps](../concerns/sandbox-and-confinement-gaps.md#host-job-test-gaps). `sandbox-exec` compiles a `-p` profile before applying it, so inside a sandboxed session a syntax error prints the SBPL reader error (exit 65) and a valid profile fails only at `sandbox_apply` (exit 71); a stage can check profile syntax but cannot run the kernel tests (`seatbelt`, `open_issues_macos_completion_kernel_*`), which the operator runs from a plain shell.
