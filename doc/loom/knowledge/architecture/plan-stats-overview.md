# Plan Stats Overview

> Finished-plan record, archive, phases, TUI and web plan overview

## Finished-Plan Statistics and the Plan Overview

When the scheduler finishes every stage, `daemon/server/orchestrator.rs::publish_plan_stats` runs `tokens::final_scan` over the work root, then `plan_stats::finish_plan`. Either failure is logged and leaves the outcome alone: the stages are done whatever the statistics say.

**Record** (`plan_stats/record.rs`, wire contract `web/src/api/schema.ts::planStatsSchema`): `PlanStatsRecord` holds `schema_version` (1), `plan_id`, `plan_name`, `started_at`, `ended_at`, `wall_secs`, `execution_secs` (the sum of the stages' counters, above wall time when stages ran in parallel), `totals`, one `StageStats` per stage (id, name, `stage_type` and `status` as serde names, times, model, effort, `phases`, tokens) and one `ModelStats` per (model, effort, lane). `deny_unknown_fields`; nullable values serialize as explicit `null`; `MAX_RECORD_BYTES` is 1 MiB, so a record always fits the 2 MiB status frame on its own.

**Identity** (`plan_stats/identity.rs`): `loom init` stamps `stats_initialized_at`, `stats_source_slug` and `stats_run_id` into the `[plan]` table (`plan_stats::stamp_new_run`, called from `commands/init/plan_setup.rs`), so `plan_id` is `<init UTC time>-<source slug>-<run uuid>` and fixes the archive name for the whole run. A run initialized without the keys gets them once under the config lock. `plan_setup.rs` also calls `remove_current` so a new run starts without the previous report.

**Archive and current copy.** `publish` writes `<loom home>/stats/plans/<plan_id>.json` (`loom_home()` is the parent of the user config file, so `LOOM_HOME` moves it; file mode 0600, directory 0700) by hard-linking a synced temporary file, so the first record of a run stays and no reader sees a partial one; the file stem is cut to `[A-Za-z0-9_-]`, 128 characters (`file_name_for`; the web's `plan-math.ts::archiveFileName` does not repeat that cut). The archive survives `loom clean`. `finish_plan` is idempotent: an existing archive is used verbatim and the current copy (`<work dir>/plan-stats.json`, `plan_stats/current.rs`) is rewritten from it, so the two always agree. `finish_plan` does not itself require every stage terminal; the caller's success guard does.

**Phases** (`models/stage/phases.rs`): `verify::transitions::persistence` calls `phases::record` on every persisted status or session change, so each span edge is a real transition time. `Phase` is `Contract`, `Executing`, `Adjudication`, `Retry` or `Waiting`; a stage keeps at most `MAX_PHASE_SPANS` (512) spans, the last slot being an overflow `Waiting` span.

**Feed.** `status/data/collector_snapshot.rs` reads the current copy into `StatusData.plan_stats`. `daemon/wire.rs` drops `plan_stats` from a response over `MAX_RESPONSE_BYTES`; the web feed keeps it out of every `state` message (`commands/status/web/feed_split.rs::FULL_ONLY_STATUS_KEYS`). Every `StageSummary` broadcast also carries up to 512 spans per stage though no live view reads them.

**Surfaces.** TUI: `commands/status/ui/tui/plan_overview.rs` is the "PLAN COMPLETE" screen in place of the ledger (scrolling body, footer pinned to the last rows from `MIN_PINNED_HEIGHT` 8; timeline in `plan_overview_timeline.rs`, model rows in `plan_overview_models.rs`); `loom status --live` with no daemon opens it from the on-disk report through `ui::run_finished_report`, at its top. The `TuiApp::headless`, `advance` and `draw_view` seams exist for the contract tests. Web: `web/src/components/plan-overview/` (`PlanOverviewDialog`, mounted by `routes/shell.tsx` while `planStatsAtom` is non-null) is a non-modal Radix dialog plus `inert` on the shell wrapper: a modal dialog cannot hide the page because `aria-hidden` `hideOthers` keeps every `aria-live` element and its ancestors, and `BusyRoundel` in the header has `aria-live=polite`. The timeline has a text equivalent. Both surfaces key a stage as skipped on its status only and draw an empty bar otherwise, and end a bar at the latest `ended_at`.

**Open items.** `plan-math.ts` tie-breaks model rows by record order while the TUI sorts by name (`plan_overview_models.rs`); `hit_text` in `ledger/header.rs` recomputes the cache-hit ratio next to `TokenUsage::cache_hit_percent` (one decimal against a whole percent); `collector_snapshot.rs::read_current` re-lists and re-parses every stage file each second; `plan_stats/sanitize.rs::MAX_SAFE_INTEGER` repeats `status/data/sanitize_token_flow.rs`; `user_config::config_path` falls back to `LOOM_HOME` or `~/.loom` in a lib test that reaches `finish_plan` on a spawned thread, which would archive into the operator's home (the `planning/runtime.rs` temp-home fallback is the model); the orchestrator thread overrunning its 5 s join timeout in `daemon/server/lifecycle.rs` can let `final_scan` overlap a stopping tracker pass writing the checkpoint (exit-time only); the manual scrim in `plan-overview-dialog.tsx` copies `DialogOverlay`'s class string.
