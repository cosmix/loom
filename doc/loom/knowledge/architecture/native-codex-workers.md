# Native Codex Workers

>

## Backend and Lane Selection

A stage's main agent starts a Codex worker with `loom subagents start --provider codex`; no Claude session sits between the lead and Codex. The daemon admits the request, starts one supervisor process per worker, and the supervisor runs `codex app-server` inside a bubblewrap boundary with its own pid namespace. The backend is the config key `codex.backend` (`native` default, `legacy`; `user_config/keys.rs`, per-key project tier; `codex_backend.rs::configured_backend`).

`codex_backend.rs::codex_lane` returns `CodexLane::{Unavailable(reason), Legacy, Native}`. No codex executable gives `Unavailable`; `Legacy` needs the companion plugin; `Native` needs `boundary::native_backend_qualified()` (`boundary/probe.rs`; a `OnceLock` caches the answer, a failure included, for the daemon's life, so installing bwrap or fixing a macOS probe needs a daemon restart). On Linux that is bubblewrap with `--size`, a payload boundary in its own pid namespace and Codex's own sandbox starting inside it. On macOS `probe.rs::qualify_macos_from` runs three `MacHostProbes` in order and the first failure is the reason: `sandbox_exec` (`/usr/bin/sandbox-exec` exists and this process is not already inside a sandbox that forbids nesting one), `payload_boundary` (the production Seatbelt launch makes the worktree writable, a host home neither writable nor readable, and releases cleanly) and `codex_home_honoured` (the resolved Codex app-server, launched through the production boundary with a controlled `CODEX_HOME`, reports that home and keeps its sessions in it). The real probes (`probe_mac.rs`, scratch in `probe_mac_fixture.rs`) run in a hermetic scratch with deadlines and retire their whole process group. A Codex that is a script wrapper (the Homebrew `codex.js`) fails `codex_home_honoured` with `is a script`: `mounts::codex_package` refuses scripts, so the lane cannot run on it. A macOS host with no usable Codex binary or inside a stage session (nested `sandbox-exec` exits 71) reports `Unavailable`, and a host that needs the forwarder sets `codex.backend = legacy` ([qualification](../concerns/native-codex-qualification.md)). A configured native backend never turns into the legacy lane silently. The signal's launch text follows the lane (`orchestrator/signals/format/codex.rs`, `codex_native.rs`; `push_codex_intro` serves Legacy and Native, `push_codex_unavailable_fallback` an unavailable lane).

Plans name the implementer (`codex`), never the mechanism; only `codex.backend` picks it, resolved at the execution layer, never from plan or signal text. `loom hook codex-backend` prints `configured_backend` for the hooks: in a live stage session with a native backend `spawn-guard.sh` denies a `loom-codex-forwarder` or `codex:*` spawn (`_spawn_policy.sh::loom_native_lane_spawn`) and `codex-forward-guard.sh` refuses any Bash call of `codex-forward.sh` (`_codex_forward.sh::loom_native_lane_forward`), both naming `loom subagents start --provider codex`; with a legacy backend `loom subagents start` refuses and names the forwarder spawn (`native_start.rs`). A missing binary or failed query keeps legacy behavior. None of these routes transparently: a hook cannot turn an Agent call into a Bash call, `loom subagents start` is lead-only while the forwarder is a subagent, and a forward's invocation id is minted only for a forwarder identity.

## Record Store

`<work_dir>/native-workers/<stage>/<invocation>/` (`native_worker/store.rs`, `store_io.rs`), directory 0700, files 0600. The boundary never mounts it and a stage session cannot write under `.loom`. It is separate from `lifecycle.jsonl` because a new `WorkerIdentity` variant would make every reader and three shell hooks reject the journal (`deny_unknown_fields`).

| File | Writer |
| --- | --- |
| `manifest.json`, brief.md | daemon, once, at admission (brief.md is a byte copy of the brief) |
| `events.jsonl` | daemon writes `Admitted`; then the supervisor only; the daemon again once the supervisor is proven gone |
| `supervisor.json` | the supervisor, first act, `O_CREAT\|O_EXCL`; or the daemon as a tombstone (`pid` 0). Whoever creates it owns the invocation |
| `boundary.pending` | the supervisor, empty, just before `boundary::spawn` (`store::mark_spawn_begun`) |
| `boundary.json` | the supervisor, once, before `initialize` is sent |
| `control/cancel.json`, `control/msg-<id>.json` | daemon or operator CLI |
| report.md, `provider.log`, `supervisor.log` | supervisor; the provider log is capped at 4 MiB |

Writes of manifest, boundary, control and report files are temp-file-then-rename with `fsync`; `events.jsonl` is append-only with `O_NOFOLLOW`, one fsynced line per append. Reads use `O_NOFOLLOW`, require a regular file owned by the current uid and read at most `MAX_RECORD_BYTES` (4 MiB). Constants live in `ids.rs`: six active workers per stage, a 1500 s deadline, 256 KiB briefs, 1 MiB frames, 16 queued messages of at most 16 KiB, interrupt grace 5 s, end-of-input grace 2 s, reap grace 2 s, a progress event every 30 s. Unit and message ids match `^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$` (no dots); invocation ids are `inv-` plus 32 lowercase hex digits; stage ids follow `validation::validate_id` (up to 128 characters, `ids::validate_stage_id`).

`model.rs` folds events into `NativeUnitState` (phase `Admitted`..`Terminal`, outcome, ownership `Held`/`Released`/`Unverified`); `index.rs` is the only read API for consumers. `NativeEvent` is internally tagged: serde ignores extra fields on unit variants even with `deny_unknown_fields`, so an unknown-field test needs a struct variant (`model_tests.rs`).

## Boundary and Proxy

`boundary/mod.rs::spawn` runs bubblewrap with `--die-with-parent --unshare-all --new-session`, a read-only root, an allowlisted environment and no network beyond loopback. The worktree is the only writable project path; `W/.loom`, `W/.git`, `W/.claude` and `W/.codex` stay read-only. The Codex home is a private 1 GiB tmpfs (`CODEX_HOME_TMPFS_BYTES`) holding only `sessions/` (created 0700 when missing), the auth files and AGENTS.md, so config.toml, rules, hooks, MCP servers, plugins and skills never load. `/etc/codex` is hidden (`hide_system_config`). The boundary mounts private tmpfs on `/tmp` (4 GiB) and `/var/tmp` (1 GiB) before any bind (`verify::criteria::bubblewrap` with `Some(linux::TMPFS_BYTES)`; the confined gate passes `None` and keeps the kernel default), then creates `/tmp/loom-tmp` (`BOUNDARY_TMPDIR`) with `--perms 0700 --dir`; `TMPDIR`, `TMP` and `TEMP` point there. `boundary/tmpdir.rs` refuses a plan whose worktree, Codex home or host `HOME`/`TMPDIR`/`CARGO_HOME`/`RUSTUP_HOME` lies under `BOUNDARY_TMPDIR`, as given or resolved, and reads the argv before `--` against `KNOWN`, the options the boundary emits with their argument counts; an unknown option or a mount target below `BOUNDARY_TMPDIR` is refused, so bubblewrap never creates ancestors inside the writable `$TMPDIR`. The Codex `workspaceWrite` turn policy (`protocol/wire.rs::turn_start`) sets `networkAccess: false`, `excludeSlashTmp: true` and `excludeTmpdirEnvVar: false`, so sandboxed commands may write only the worktree and `$TMPDIR`; `/tmp` itself stays unwritable to them, so nothing bound below it (the Cargo scratch, a worktree under `/tmp`) can be renamed away. The proxy socket directory is bound read-only at `/loom-proxy` (`boundary/linux.rs::PROXY_DIR`, `bind_launch`) and `worker-exec` receives `--proxy-socket /loom-proxy/p.sock`. Why the temp dir is narrowed to `$TMPDIR`: [Native Worker Temp Dir](../mistakes/codex-worker-briefing.md#native-worker-temp-dir). The decisions behind the mount rules, each pinned by a boundary test:

- A symlinked `W/.git` is refused. A real `W/.loom/work` directory is hidden with `--tmpfs` plus `--remount-ro`; a `.loom/work` symlink that resolves into `W` is refused.
- The codex package directory is bound whole only for a standalone release (`<release>/bin/codex` beside `codex-package.json`); any other layout binds the executable alone. A package root that contains HOME, the codex home or the worktree is refused, so a codex at `~/bin/codex` cannot expose `~/.ssh`.
- `PATH` gains `<CARGO_HOME or HOME/.cargo>/bin` ahead of `/usr/local/bin`. The Cargo home is the boundary's own (`CargoScratch::prepare_private`): mounted over the host Cargo home path, or, when that cannot be remapped, a Linked home at `<.loom-command-*>/cargo`, removed with the boundary. The boundary never binds the persistent per-tree `.loom-cargo-*` home the confined gate uses, so no worker can plant a Cargo config (`build.rustc-wrapper`) for a later worker or the gate. Command scratches (boundary and confined gate) are named `.loom-command-<pidns>-<pid>-<start>-*` (`verify/criteria/confine_scratch/reclaim.rs`) and are created only under sweepable roots: root-owned and sticky, or the user's own directory that no group or other user can write. The first scratch a process creates starts a background sweep of same-uid, same-namespace scratches whose owner is gone; removal first restores owner `rwx` with a descriptor walk that never follows a symlink (`removable.rs`). A boundary scratch carries a `.loom-boundary` marker (`marker.rs`: boot id and pid-namespace inode, written before bubblewrap starts). A supervisor or probe that cannot prove the namespace empty (`kill_namespace` signals only verified members through a pidfd) keeps the scratch, as does any scratch dropped during a panic; the sweep reclaims it once its owner is gone and the marker's boot id differs from the current one or its namespace has no members; only an unreadable marker or boot id falls back to the scratch's age (ctime before `/proc/stat` btime). Bubblewrap closing its info pipe without a report (`InfoError::NotReported`) may still have cloned a namespace, but its child closes that fd and blocks on its wait fd before mounting anything or `setsid`, so the group SIGKILL reaches it and nothing is bound: the scratch is removed and the failure settles as unspawned. A partial, malformed or late report is ambiguous and keeps the scratch. When the supervisor cannot read the boundary's identity, `teardown::stop_unrecorded` kills the namespace and settles ownership Released only if it is proven empty. The probe passes no HOME, so uv and bun overlays are skipped.
- Codex's own sandbox always runs in workspace-write mode. It is what keeps commands off the proxy: with network denied, Codex's seccomp filter refuses AF_INET sockets and AF_UNIX `connect` and gives commands their own network namespace, so they reach neither the bridge's loopback port nor `/loom-proxy/p.sock` (checked with codex 0.169 `codex sandbox`, nested in a bubblewrap boundary). Without it no control separates commands from the app-server: they share its uid and pid namespace and can read its environment from `/proc`. `native_backend_qualified` (`boundary/probe.rs::qualify_from`, real probes in `probe_host.rs`) therefore requires bubblewrap with `--size` (0.10 or later), a payload boundary in its own pid namespace, and `codex sandbox` in workspace-write mode (no network, `/tmp` excluded) succeeding inside a payload boundary that binds the Codex package. Codex runs the first executable `bwrap` on the boundary's PATH, else the release's `codex-resources/bwrap`; the refusal names that path. Otherwise the lane is UNAVAILABLE and codex-tier work goes to Claude. Execpolicy `allow` rules, hooks and MCP commands would run outside Codex's sandbox; the boundary loads none of them.

`boundary::verify_quiescent` is the only proof of release: the boot id matches and no process visible in `/proc` carries the recorded pid-namespace inode (a different boot id means released). A `PermissionDenied` readlink counts as not-a-member only when `/proc/<pid>/status` shows a foreign real and effective uid or a single `NSpid` entry; trusting the directory owner would let a member hide with `PR_SET_DUMPABLE 0`.

`proxy/` serves an allowlist CONNECT proxy on a Unix socket. `connect_target_allowed` splits at the last colon, requires port exactly 443, lowercases the host and strips one trailing dot, refuses IP literals, empty or bracketed hosts and any character outside `[a-z0-9.-]`, and matches exact entries or `*.suffix` (never the bare suffix). The proxy refuses a resolved loopback, private or link-local address. The allowlist is `crate::codex::CODEX_SANDBOX_DOMAINS`. Inside the boundary `bridge.rs` (`loom subagents worker-exec`) exposes the socket on loopback TCP and sets the proxy variables. The proxy inspects no TLS ([exposure facts](../concerns/native-codex-qualification.md#exposure-facts)). Dropping the handle joins handlers that may block in name resolution, which delays supervisor exit.

## Supervisor, Runner and Settlement

`supervisor/mod.rs::run_session` drives a pure reducer (`machine/`: `Machine`, `Input`, `Action`) over a `Transport` and a `Clock`, so tests use a scripted peer. Each iteration polls control files (`control.rs`, about 200 ms), receives one frame, then feeds `Deadline` and `GraceElapsed` inputs and writes a `Progress` event after 30 quiet seconds. The machine arms a startup deadline (`machine::STARTUP_DEADLINE_SECS`, 120 s, action `ArmStartupDeadline`) that fails the invocation when the Codex thread has not started by then (`machine/turns.rs`); the supervisor checks it against the clock read before `recv`, which blocks up to `RECV_TIMEOUT` (200 ms), so a handshake frame arriving that much past the deadline is still accepted (bounding the receive by the time left would close it). The startup contract test drives `run_session` with a local timed transport and a fake clock instead of the shared scripted peer. `PipeTransport::send` uses `try_send` on a 64-frame queue; a full queue is `TransportClosed`, so a provider that stops reading stdin never stalls cancel or deadline handling. A provider request for user input gets an error reply and a `ServerRequestRefused` event. Usage comes from rollouts under the shared `~/.codex/sessions` (the supervisor opts out of `thread/tokenUsage/updated`).

Teardown (`supervisor/teardown.rs`) closes the app-server's input, waits `EOF_GRACE_SECS`, kills the outer bubblewrap process, runs `verify_quiescent`, then appends `Terminal` and `OwnershipReleased { by: "supervisor" }` or `OwnershipUnverified`. A failure before any namespace exists (proxy start, bwrap spawn) settles `Released` without a check.

`runner.rs::NativeRunner` (daemon side) spawns one `loom subagents supervise` per invocation only when `supervisor.json` is absent and this process has not spawned for it, never retries a spawn, and holds children as plain `Child` because a supervisor outlives the daemon. A reaped child is settled by the next recovery pass (`runner_recover.rs`, every 5 s, claim rules), not in `reap`, because a supervisor from an earlier daemon may still own a young record; a spawn failure tombstones `supervisor.json` before writing `Failed` and `Released`. `settle_lost_supervisor` releases without proof only when `boundary.pending` is absent; marker present and `boundary.json` absent records `Failed` and `OwnershipUnverified`.

## Admission and Ingress

`RequestKind::WorkerControl` (wire name `subagents:control`, `relay/kind.rs`) is a control kind allowed for `SessionType::Stage` only; `payload_native.rs` carries `Start`, `Message` and `Cancel`. `inbox_drain/worker_control.rs` calls `native_worker::admission` under the existing `fs/stage_admission` lock, which closes the check-then-launch race. `admit_start` checks in order: ids, model in `CODEX_MODELS`, effort in `CODEX_EFFORTS`; the stage's `implementers` includes codex; the brief (absolute, opened `O_NOFOLLOW`, regular, canonical path inside the stage worktree, at most 256 KiB, UTF-8, sha256 match); `stage_disposition` is not `Unverified`; an identical request for a running unit returns `AlreadyAdmitted` and a different one is refused (idempotency by unit id, no caller key); fewer than six non-terminal invocations. It does not require the stage to be `Executing` ([concerns](../concerns/native-codex-qualification.md#unimplemented-review-suggestions)). Start is admitted on a host that cannot qualify the backend and fails later in supervisor preflight.

The CLI (`commands/subagents/native_start.rs`, `native_control.rs`) is `start`, `message`, `cancel`, `release` (operator only), `status`, `result`, plus hidden `supervise` (refuses when `LOOM_SESSION_ID` or `LOOM_STAGE_ID` is set) and `worker-exec`. `start`, `message` and in-session `cancel` validate locally (refusals exit 3 before any ticket exists), write one ticket, print the relay line and exit 0, because a non-zero exit after submission would skip the relay hook and strand the ticket against the 32-ticket quota. `loom-hooks/loom-control-subagents.sh` pins the exact command spelling, accepts only the stage's main agent and accepts `--unit` as an alias of `--unit-id`. Ledger notes: `native worker <unit> admitted as <inv>`, `... already admitted as <inv>`, `message <id> accepted for <inv>`, `cancel requested for <inv>`.

## Consumer Gates

`native_worker::index::stage_disposition(work_dir, stage_id)` is stage-wide (it ignores the session id, so a worker from an earlier attempt still counts) and returns `None`, `Active(units)` or `Unverified(cause)`. `blocker(stage_id)` renders the refusal: `Active` names `loom subagents cancel`; an unproven-ownership cause (exactly `<inv-id>: processes not proven stopped`) names `loom subagents release --stage <s> --invocation <id>`; any other cause is a damaged record or stage directory (a stage-level cause starts `stage <id>:`) and the remedy is manual removal. `Unverified(String)` stays a string variant because `park.rs` matches it with `if let`.

Every gate calls it, and `--force` cannot bypass any of them: `commands/stage/native_gate.rs::ensure_no_native_workers` (called from `commit.rs`, `complete.rs` Knowledge branch, `complete_pipeline.rs`, `skip_retry.rs`, `orchestrator/skip.rs`), `orchestrator/core/stage_spawn.rs`, `inbox_drain/commit.rs`, `host_verify/submit.rs` and `apply.rs`, and `loop_recovery/park.rs`. Monitors read it too: `monitor/hung_latch.rs` (`native_held`) and `status/data/heartbeat_facts.rs`. Waits bind a `codex:<unit>` selector to the native record when one exists (`wait/native.rs::outcome_for`: `Unverified` ownership is `Unknown`, a non-terminal record quiet past the stall budget is `Stalled` and exits 6, `Terminal` with ownership `Held` is still `Active`). Token attribution reads `index::stage_threads` (`tokens/discover.rs`, `commands/usage/forward_join_native.rs`), which carries each thread's `unit_id` and manifest effort onto its codex `AgentFlow`. Status reads the index twice: `status/data/execution_models.rs` lists `model/effort (requested)` per thread, and `status/data/codex_jobs.rs` turns `index::stage_jobs` (`native_worker/index_jobs.rs`) into the stage's `codex_jobs`, one entry per invocation including those that never started a thread. The web stage modal (`web/src/lib/codex-jobs.ts`, `stage-token-lanes.tsx`) and the TUI tokens pane (`ledger/tokens_jobs.rs`) render each job by unit id with its outcome and its duration against the deadline; a job without a thread gets a row with no tokens.

## Session Grants

`sandbox/settings/policy.rs::codex_granted` is `implementers.includes_codex() && backend == Legacy`, so a native-backend session gets no `~/.codex` write grant, no OpenAI domains and no readable `auth.json` ([Where a Session's Write Grants Come From](security-and-isolation.md#where-a-sessions-write-grants-come-from)).

## Testing Limits

Acceptance runs in a confined host job with no network and no `~/.codex`, so every test uses a scripted peer. Inside a sandboxed subagent `UnixListener::bind` fails with `EPERM` (proxy server tests) and bubblewrap cannot create a namespace, so `skip_unless(confined_commands_runnable())` boundary tests skip there and about 58 unguarded `verify::criteria` confine tests fail regardless of code; the `loom check` host job is the judge. Runtime contract helpers live at `native_worker::runtime_contract_tests::testkit` through a `#[path]` attribute; `native_worker/mod.rs` declares no `testkit` module. Seed test invocations with `sha256_hex(b"brief")` (`store::create_invocation` validates the digest against the brief bytes).

## Tracing Native Workers

`nativeBackend` in `web/src/components/stage-modal.tsx:104` means `session_backend === 'native'`, a native terminal window; it has no relation to a native Codex worker (`loom/src/native_worker`). Search `native_worker`, `codex.backend` and `WorkerControl` when tracing the lane.

## macOS Boundary (Seatbelt)

The macOS lane has no pid namespace. `boundary/macos.rs` runs the trusted bridge (`loom subagents worker-exec`) under `/usr/bin/sandbox-exec -p <profile>` in a fresh session (`setsid`, so the leader's pid is also the session and group id) with a clean environment and two inherited descriptors: the loopback listener the supervisor prebound (it stays held until retire, so its port stays reserved) and the bridge's control channel. One Seatbelt profile is the only boundary, because macOS refuses a sandbox started inside another one.

- **Profile** (`seatbelt_profile.rs`, spec in `macos_spec.rs`). Rule order is the policy, last match wins: deny by default; runtime access; the proxy socket connect and `network-inbound` on `localhost:<port>` only, with no `network-bind` (the supervisor bound the listener); reads below the read roots; writes below the worktree, the private root's `tmp/` and `codex-home/`; the toolchain files outside the roots as the completion profile lists them (`seatbelt_host_files.rs` reuses `verify::criteria::ancestors` and `seatbelt_files`); then protected-path write denies (`.git`, `.loom`, `.claude`, `.codex` in the worktree), hidden-path denies (real Codex home, system Codex config, `.loom/work`) and read-only re-allows of the map stores below a hidden path. Every path rule names each spelling (`/var`, `/private/var`, `/tmp`, `/private/tmp`, `/System/Volumes/Data`). Profile contracts evaluate the rendered SBPL with an in-test reader (`seatbelt_profile_contract_tests.rs`), so any rule layout that has the right effect passes.
- **Confinement proof.** The bridge confirms `sandbox_check(getpid(), NULL, 0) == 1` and `getsid(0) == getpid()`, sends `READY` over a socketpair and waits for `GO` from the supervisor (`handshake.rs`); a peer that closed gives `EINVAL` on `set_read_timeout`, reported as "the bridge exited before confirming".
- **Private root** (`private_root.rs`). Per invocation `<stage cache>/native/<id>/{codex-home,tmp}`, created and removed with `openat`/`fstatat` walks that never follow a link and check ancestors by `lstat`. `auth.json`, its locks and the Codex agents file are copies that Codex can read but not write; Linux binds them read-write. No Codex configuration file is copied, so operator configuration never loads.
- **Rollout reclaim** (`private_root_rollouts.rs`). Only after `verify_quiescent` proves the boundary released, regular `rollout-*.jsonl` files with one link move from the private `codex-home/sessions/` to the same relative path below the host sessions tree (`provider_data::codex_discovery::codex_root`), where token discovery reads them; same-device `rename`, else a verified copy through a `.loom-partial` file. A failed move leaves the record `Unverified` with the root kept, so recovery or an operator release retries. Native macOS rollouts therefore reach live token totals only after release ([Token Flow Sources](token-flow-sources.md#token-usage-sources)). The module compiles on every OS; on Linux the macOS identity is always `None`, so nothing moves.
- **Process census and its limits** (`process/macos_procs.rs`, `quiescence_scan.rs`, `quiescence/mac.rs`). One `sysctl(KERN_PROC_ALL)` read gives pid, parent, group, uids, run state and start time, parsed from `kinfo_proc` at fixed offsets (size 648); `getsid` and `KERN_PROCARGS2` (the environment) are read per pid afterwards. A process belongs to the boundary when it keeps the session, the group or the `LOOM_NATIVE_BOUNDARY=<invocation id>` environment entry, or descends from one that does. A failed `getsid` or `KERN_PROCARGS2` read is `Gone` only when `is_process_alive` confirms the pid dead or a zombie; the errno alone is never trusted, so a permission failure is `Denied` and keeps the verdict `Unverified`. Known limits: a process that called `setsid`, was reparented away from every matched ancestor and overwrote its initial environment escapes the scan (it stays inside the Seatbelt profile); a setuid-exec'd process looks like another user's and its unreadable environment is ignored; `verify` always seeds by number, so a recorded session number reused by an unrelated live session gives a permanent `Unverified` until reboot; `kill_mac` signals the group only while the leader's recorded start time pins the number, then one process at a time with a start-time check before each signal, leaving one window (pid reuse between that check and the signal). Inside an agent-session sandbox `kern.bootsessionuuid` (the boot id) fails with `EPERM` and `KERN_PROCARGS2` is denied for processes the session did not start, so the census proofs read `Unverified` there and need an unconfined host.
- **Known gaps** ([qualification concerns](../concerns/native-codex-qualification.md#macos-support)): no PTY grants (`/dev/ptmx`, file-ioctl), no writable Cargo home or stage-cache environment (Linux has `CargoScratch`), auth copies read-only so a refreshed token cannot persist, and Codex-home writes outside `sessions/` are denied.
