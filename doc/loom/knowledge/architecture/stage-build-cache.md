# Stage Build Cache

> Per-stage cache root: env, seeds, sockets, read roots, xcrun bypass

## Stage Build Cache: One Root Per Stage For Every Confined Consumer

A stage has ONE persistent build-cache root outside its worktree, `StageCache` (`loom/src/stage_cache/mod.rs`). Its session, its Linux codex workers and every confined run (the host jobs for contract freeze, `loom check`, stage completion and before-stage checks, plus provisioning, which the orchestrator's pre-spawn gate runs confined with `NetworkAccess::Provision`, `orchestrator/core/provision_gate.rs`) point each tool's cache there, so a stage's code can poison only its own cache. Host caches are read-only seeds where a tool layers them. Cargo and rustup are the exception: their homes also hold toolchains and credentials, so `sandbox/package_caches.rs` still grants them to sessions and the Cargo home stays the host's path (see [execution containment](execution-containment.md#read-this-first-what-containment-means-in-loom)).

### Root and lifecycle

- `StageCache::resolve(repo_root, stage_id, home, xdg_cache_home)` returns `<base>/loom/stage-cache/<24 hex of sha256(canonical repo root, NUL, stage id)>`; `<base>` is an absolute `$XDG_CACHE_HOME`, else `~/Library/Caches` (macOS) or `~/.cache` (Linux). The fixed-length name keeps `<root>/<socket>` under SUN_LEN. `StageCache::resolve_from_process` is the only resolver that reads the environment; launch, host jobs and cleanup all call it, so cleanup removes the root launch created (`stage_cache/cleanup_tests.rs` pins the agreement).
- `ensure()` creates the root 0700 one component at a time with `O_NOFOLLOW` and refuses a symlinked or foreign-owned root or parent. `remove_stage_cache` (`stage_cache/cleanup.rs`) opens `loom/` and `stage-cache/` the same way and deletes through the shared no-follow walk `fs/no_follow_tree.rs`, which `verify/criteria/confine_linked_home.rs` also uses. The walk stops at `MAX_DEPTH` 64.
- Removal runs from the worktree cleanup (`git/cleanup/batch.rs`), `orchestrator/merge_lifecycle.rs::remove_worktreeless_cache` (a stage with no worktree, deferred while a live session may use it; a failure is a warning on the stage record) and `loom init --clean` (`commands/init/cleanup.rs`).
- Sessions: `orchestrator/terminal/launch/prepare/host.rs::stage_cache` ensures the root before the capsule names it (Claude Code skips a missing `allowWrite` path), `stage_cache/session.rs::apply_session_grant` adds it to `allowWrite`, and `wrapper_exports` renders the session environment into the wrapper's `exec env -i` line. Linux workers: `native_worker/boundary/environment.rs::with_stage_cache`. Host jobs: `verify/criteria/confine.rs::confined_stage_cache(work_dir, stage_id, confinement)`, which returns `None` for `Inherit`; `commands/stage/acceptance_runner.rs`, `host_verify/child.rs`, `verify/completion/{mod,resolved}.rs`, `verify/contracts/{freeze,completion}.rs`, `verify/goal_backward/plan.rs` and `orchestrator/core/stage_preflight.rs` thread the same cache.

### Host seeds come from loom's own environment

`stage_cache::host_env_from_process()` reads nine names (`HOST_ENV_NAMES`): `HOME`, `PATH`, `GOPATH`, `GOMODCACHE`, `CCACHE_DIR`, `XDG_CACHE_HOME`, `GRADLE_USER_HOME`, `GOPROXY`, `GOFLAGS`. The daemon allowlist (`daemon/server/environment.rs`) keeps them. A confined command's own environment (`STAGE_HOST_ENV_ALLOWLIST`) lacks the location variables, so reading seeds from it silently drops them: every consumer, including the Linux worker boundary, resolves seeds from the process environment. A `GOPROXY` with URL userinfo in any entry is dropped whole (`goproxy_has_userinfo`); `MAVEN_OPTS` is never read because it carries proxy passwords. See [the credential-forwarding mistake](../mistakes/ci-gate-rollout.md#forwarding-the-hosts-goproxy-and-maven_opts-into-sessions-leaked-credentials).

### Environment (`StageCache::environment(consumer, worktree_root, host_env, developer)`)

| Tool | Set (paths under the root) | Read-only seed |
| --- | --- | --- |
| Go | `GOCACHE=go-build`, `GOMODCACHE=go-mod`, `GOPROXY=file://<seed>/cache/download,<tail>` (tail: host `GOPROXY` or `https://proxy.golang.org,direct` for session, worker and provisioning; `off` for a host job), `GOFLAGS` with `-count=1` added for a host job so a planted `GOCACHE` test result cannot print `ok (cached)` | host `GOMODCACHE`, else first `GOPATH` entry, else `~/go`, + `pkg/mod` |
| ccache | `CCACHE_DIR=ccache`, `CCACHE_BASEDIR=<worktree root>`; with a seed `CCACHE_REMOTE_STORAGE` and `CCACHE_SECONDARY_STORAGE=file:<seed>\|read-only` | host `CCACHE_DIR`, else the platform default |
| sccache | `SCCACHE_DIR=sccache`, `SCCACHE_SERVER_UDS` (below) | none |
| Maven | `MAVEN_OPTS=-Dmaven.repo.local=<root>/m2` plus `-Dmaven.repo.local.tail=<seed>` | `~/.m2/repository`; Maven older than 3.9 ignores the tail |
| Gradle | `GRADLE_USER_HOME=gradle`, `GRADLE_RO_DEP_CACHE=<seed>`, `GRADLE_OPTS=-Xmx1g` (Gradle 8.10 `canUseCurrentProcess` reuses the client JVM unless its heap is at most 64 MB, the start script's `-Xmx64m`, or the build sets `org.gradle.jvmargs`, which must then equal the client's args exactly; so `--no-daemon` builds in-process; the host's `GRADLE_OPTS` is never read). Confined Gradle is unsupported on macOS: Seatbelt denies the UDP bind Gradle makes for every cache lock and the loopback TCP its compiler and test workers use ([Confined Gradle Is Unsupported on macOS](../concerns/state-confinement-gaps.md#confined-gradle-on-macos-needs-the-loopback-opt-in)) | host `caches` when `caches/modules-2` exists |
| npm, pnpm, yarn, bun, deno, uv, pip | `npm_config_cache`, `npm_config_store_dir`, `YARN_CACHE_FOLDER`, `BUN_INSTALL_CACHE_DIR`, `DENO_DIR`, `UV_CACHE_DIR`, `PIP_CACHE_DIR` | none |
| anything else | `XDG_CACHE_HOME=xdg` | none |

### Sockets: one sccache server per consumer

An sccache server runs the compilers its clients ask for, so a client reaching another consumer's server would run commands outside its own confinement. The consumers share `SCCACHE_DIR` and nothing else: a host job's `h.sock` lives in a directory only that command reaches (`verify/criteria/confine_scratch.rs::sccache_socket_dir`: the private `/tmp` under bubblewrap, the command's scratch on macOS); a session's `s.sock` lives in the session scratch dir and a Linux worker's `w.sock` on its private `/tmp` (`StageCache::with_socket_dir`; without one `environment` omits `SCCACHE_SERVER_UDS`, so a caller that forgets cannot fall back to the shared root). bubblewrap cannot filter path-based Unix sockets and binds the whole root for host jobs, which is why the other consumers' sockets are not in it. The variable is omitted when the path would not fit SUN_LEN (104 on macOS, 108 on Linux); sccache then falls back to localhost TCP, which Seatbelt denies, so a long `TMPDIR` or a temp-dir HOME turns sccache off. Seatbelt (`verify/criteria/confine_seatbelt.rs::scratch_socket_rule`) allows bind and connect below the command's own scratch `TMPDIR`, where the sccache client binds its startup-notification socket; Seatbelt matches a socket's resolved path, so a symlink in that `TMPDIR` reaches no host socket (`a_tmpdir_symlink_does_not_reach_a_host_socket`). Provisioning keeps `(allow network-outbound)` but denies Unix-socket connects below the stage-cache base and the session scratch base (`provision_network_rules`), the scratch socket grant still winning. Residual: [provisioning keeps a blanket outbound allow](../concerns/state-confinement-gaps.md#open-reviewer-suggestions-from-the-stage-cache-plan).

### Read roots, writable roots, order

- `confine_read_roots.rs::read_roots_beside` adds, read-only and for existing paths: the seeds; the toolchain roots under HOME in `stage_cache/roots.rs::TOOLCHAIN_ROOTS` (`.local/bin`, `.local/pipx`, `go/bin`, `sdk`, `.bun/install/global`, `.nvm/versions`, `.volta`, `.local/share/fnm`, `.sdkman/candidates`, `.asdf/installs`, `.local/share/mise/installs`, `.pyenv/versions`, `.jdks`, `.deno/bin`); `/opt` and `/nix/store`; and every `PATH` entry below HOME, never HOME itself and never an entry that is, contains or lies inside a credential directory. Each such entry also grants its install root when the parent has a recognised toolchain layout and no project marker (`stage_cache/install_roots.rs`: Go, JDK including macOS `Contents/Home`, Node, Gradle, an actions tool-cache `<version>/<arch>.complete`), and the `bin`/`sbin` directories its executables' symlinks resolve to, below HOME and outside hidden HOME children. An entry, root or symlink whose resolution reaches a writable root is dropped before expansion (`stage_cache/writable.rs::Writable::reached_by`), so a command cannot plant links that widen a later command's reads; nested roots collapse to the outermost. Roots are filtered against the boundary's canonical writable roots: Seatbelt `deny file-write*` and bubblewrap `--ro-bind` come after the writable grants, so a PATH entry inside or containing the tree (`target/debug/deps`, `~/src`) would otherwise make the tree read-only. The Linux worker boundary keeps `read_roots()` (installation roots only) and adds the same roots itself.
- Writable: the stage cache root. Under Seatbelt `~/.m2/settings.xml`, `settings-security.xml` and `toolchains.xml` are hidden by name (`HIDDEN_IN_M2`): Maven fails on a file it can see but not read.
- `confine_host.rs::apply_stage_cache` runs after `CargoScratch::apply_environment`, so scratch values never win. Without a stage cache (plan dry-run, `spawn_confined`, `format_problems`, tests) the per-command scratch caches and the Linux uv/bun overlays apply unchanged; with one the overlays are not mounted. Provisioning with a cache takes the Session `GOPROXY` chain (`go_proxy`), because `off` would fail `go mod download`.

### macOS developer tools bypass the xcrun shims

`stage_cache/developer.rs::DeveloperTools::detect()` runs `xcode-select -p` and `xcrun --sdk macosx --show-sdk-path` once per process, unconfined, where xcrun's cache works. `DeveloperTools::environment` (`stage_cache/environment.rs`) puts `<developer dir>/Toolchains/XcodeDefault.xctoolchain/usr/bin` (when present) and `<developer dir>/usr/bin` ahead of the host `PATH` and sets `SDKROOT` and `DEVELOPER_DIR`, identically for every consumer so session and host-job builds share build-script inputs (cc-rs reruns on `SDKROOT`). `verify/criteria/confine.rs::apply_confined_environment` applies it to every confined command, with or without a stage cache: a plan dry run has none, and its cold builds compile C dependencies such as `aws-lc-sys`. A bare `git` or `cc` then resolves to the real binary instead of a `/usr/bin` shim, which without xcrun's cache starts `xcodebuild` on every call: 5 x `git --version` took 7.35 s through the shim and 0.066 s through the real binary; one `cc -c` 1.50 s against 0.05 s. xcrun's own cache database (`xcrun_db` under `DARWIN_USER_TEMP_DIR`) stays denied: a writable one would let a confined command plant tool paths the operator's builds follow. Residual: [a non-default SDK still pays](../concerns/sandbox-and-confinement-gaps.md#xcrun-shims-are-bypassed-not-cached).

### Test and CI notes

- Under `cfg(test)` the cache root is `<work_dir>/cache-home` (`crate::test_cache_env`). A test that reaches `stage_cache_for` or `confined_stage_cache` pins `HOME` through it; unpinned, every run creates `<HOME>/Library/Caches/loom/stage-cache/<hash>` per temp repo and never removes it. Inside the repo cwd of a non-Stage launch `sandbox/grant_paths.rs::is_inside_cwd` drops the capsule `allowWrite`, so launch tests prove the grant for `Stage` only.
- Frozen contract tests that run confined fail inside a sandboxed agent session with `sandbox-exec: sandbox_apply: Operation not permitted` (exit 71); `host_launcher().is_some()` does not detect nesting. They run in the unsandboxed gate or CI. `sandbox-exec -p '<profile>' /usr/bin/true` still validates SBPL syntax in a session (parse error: `unbound variable`, exit 65), but only names and syntax: a filter in the wrong context (vnode-type inside `remote unix-socket`) parses, so Apple's own profiles' `path-literal` is the only filter used there.
- CI (`.github/workflows/ci.yml`) installs every toolchain on the Linux and macOS runners, seeds the host caches, and runs `cargo test --lib -- stage_cache:: verify::criteria::confine::host::stage_cache_tests::` with skips fatal, so a missing toolchain or launcher is a red build. Quote any `run:` value ending in `::` (an unquoted one is a YAML mapping error). Gradle is pinned with `gradle-version`.

## The macOS Completion Profile (Seatbelt) and Its Shared Builders

`verify/criteria/confine_seatbelt.rs::profile` renders the completion boundary as a pure function, compiled on macOS and on Linux test builds, so its policy contracts run on Linux too; `platform_command` only adds the launcher check, and only macOS applies the profile. Off macOS the protected-path rules refuse instead of rendering and no host Cargo home is named, because `confine_protected.rs` and `confine_scratch.rs` gate those helpers to macOS. The file rules for single host files outside the tree live in `confine_ancestors.rs` (the directories above the tree listable, each ancestor's Cargo files hidden by name, `package.json` readable for Node's package-scope lookup) and `confine_seatbelt_files.rs` (Cargo and Maven secrets hidden, Cargo's state files and the per-user Git ignore and attributes files readable); the native worker's profile reuses them through `native_worker/boundary/seatbelt_host_files.rs` ([macOS Boundary](codex-concurrency.md#macos-boundary-seatbelt)), and `quote`/`quote_checked` (SBPL quoting that refuses a control character) are the native profile's. `quote_checked` validates only the listed paths and its closure unwraps for any other path the rule builders pass; today those are ancestors of checked paths.

**Ancestor files** (`verify/criteria/confine_ancestors.rs`). Seatbelt allows metadata reads everywhere and denies only content, so a file above the tree that Cargo searches past its first hit (an ancestor `Cargo.toml`, `.cargo/config.toml`) satisfies `exists()` and then fails on read, and Cargo aborts with exit 101 and no `could not compile`; under bubblewrap the file is unmounted and absent. Each existing such file is denied for `file-read*`, `file-read-metadata` and `file-test-existence` by name: a `file-read*` deny does not override an unfiltered `file-read-metadata` allowance, and `access(F_OK)` is its own operation. `package.json` files above the tree are readable by `literal` path instead (Node's package-scope lookup fails on `EPERM`), and each ancestor directory is listable by `literal` path (Bun aborts on an unreadable one).

**Path quoting.** The profile's `quote()` refuses any path with a character below U+0020 rather than skipping that path's deny: `serde_json` escapes such characters as `\u0001` or `\b`, which SBPL does not document, skipping only an ancestor deny would make Cargo fail on the visible file with no hint of the cause, and allow rules cannot be skipped.

Network: `NetworkAccess` (`confine_host.rs`, re-exported from `verify/criteria/mod.rs`) grants loopback only on the `allow_local_binding` opt-in, never by default ([Seatbelt loopback grant](../mistakes/native-macos-delivery.md#a-seatbelt-localhost-listener-was-re-added-as-if-it-held-binds-to-loopback)). Provisioning keeps a blanket outbound allow but denies Unix-socket connects below the real stage-cache and stage-base bases (`process_cache_bases`); the residuals of the loopback grant are in [macOS confined networking](../concerns/state-confinement-gaps.md#macos-confined-ip-networking-is-off-by-default) and [sandbox gaps](../concerns/sandbox-and-confinement-gaps.md#host-job-test-gaps). `sandbox-exec` compiles a `-p` profile before applying it, so inside a sandboxed session a syntax error prints the SBPL reader error (exit 65) and a valid profile fails only at `sandbox_apply` (exit 71); a stage can check profile syntax but cannot run the kernel tests (`seatbelt`, `open_issues_macos_completion_kernel_*`), which the operator runs from a plain shell.
