# 09 — Session Skills and Guidance

## Launch and delivery

Each session the app starts receives a brief, an opening message, and a plugin directory, all generated by the server at launch, and nothing is installed into `~/.claude` or changed in the project. [The model in one paragraph](../../../product/section_09.md#the-model-in-one-paragraph)

The brief travels in the appended system prompt, the opening message in the positional prompt, and the plugin through `--plugin-dir`, with no SessionStart hook carrying the brief. [Delivery](../../../product/section_09.md#delivery)

The plugin ships the step skills, the summary and overview agents, and the pressure commands, and each session's plugin carries only the parts its kind needs. [The plugin](../../../product/section_09.md#the-plugin)

Authoring sessions run on opus, at medium effort for spec steps and high effort for plan steps, while background summary sessions run on sonnet at high effort. [Models and effort](../../../product/section_09.md#models-and-effort)

## Steps and writing

The brief for an authoring session states what the session is, that the documents are the truth, the conventions, the write limits, the turn-end duty, and the closing message. [The common brief](../../../product/section_09.md#the-common-brief)

Each step skill holds the procedure for one kind of work, and a chat the user moves to other work loads the matching skill in the same chat. [Steps and their skills](../../../product/section_09.md#steps-and-their-skills)

Each opening message names the step and the target document, and a chat with no offer receives the brief with `Step: none chosen`. [Opening messages](../../../product/section_09.md#opening-messages)

Sessions record each decision in the document it binds as soon as the user settles it, and the closing message asks the session to write what is unrecorded and to list open questions. [Recording as you go, and the closing write](../../../product/section_09.md#recording-as-you-go-and-the-closing-write)

Write limits keep planning sessions under `doc/`, make locked plans and run reviews read-only, and forbid git, branching, and execution commands. [Write limits](../../../product/section_09.md#write-limits)

## Checks and summaries

After a turn that edits documents, the session runs `loom plan check` and rebuilds the affected summaries in two waves, document summaries first and then overviews. [Summaries after a turn](../../../product/section_09.md#summaries-after-a-turn)

A background summary session rebuilds summaries only, never asks the user anything, and runs on the overview model. [Summary sessions](../../../product/section_09.md#summary-sessions)

The `loom plan check` command prints the project checklist and every convention problem in `doc/` without needing a running server. [Checking conventions: `loom plan check`](../../../product/section_09.md#checking-conventions-loom-plan-check)

The user's own CLAUDE.md files and settings load beside the plugin and brief, and loom neither edits nor suppresses them. [The user's `CLAUDE.md` files and other ambient guidance](../../../product/section_09.md#the-users-claudemd-files-and-other-ambient-guidance)

The launch command, the summary file rules, and the pressure runs belong to sections 07, 04 and 11, and this section leaves them out. [Out of scope for this section](../../../product/section_09.md#out-of-scope-for-this-section)
