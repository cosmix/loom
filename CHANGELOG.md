## [0.8.x] - 2026-09-19

Entries marked *(unreleased)* postdate the latest 0.8.x tag.

### Added

- **Custom Claude and Codex asset roots** *(unreleased)* — set `LOOM_CLAUDECODE_INSTALL_DIR` or `LOOM_CODEX_INSTALL_DIR` to relocate either install tree for the source installer, `loom install-assets`, and asset refreshes after `loom update`; explicit `--claude-dir` and `--codex-dir` flags still take precedence.
- **A two-scope interactive config editor** *(unreleased)* — bare `loom config` now edits both `~/.loom/config.toml` and the current repository's `.loom/work/config.toml`, shows which tier supplies the effective value, stages changes independently per scope, and preserves failed writes for retry.
- **Cumulative changelog command** — the installed `/changelog <next-version>` command audits every commit since the previous release tag for substantial user-facing changes and updates the cumulative minor-series section; release extraction accepts headings such as `0.8.x` when packaging a patch release.
- **State confinement and the session relay** — every session kind now launches from its own settings capsule that denies writes to `.loom/`, `.claude/`, `.worktrees/`, the hooks directories, git hooks and config; a sandboxed agent's `loom memory`, `loom stage block`, `loom stage dispute-criteria`, `loom handoff`, `loom stage merge --resolved`, `loom worktree remove` and telemetry calls write a ticket that a `PostToolUse` relay hook hands to the daemon, which applies each request at most once through a per-session ledger. `loom request status <id>` reports where a relayed request stands, and the daemon refuses to merge or hand to a resolver any branch whose diff touches `.claude/`, `.mcp.json`, `.loom/` or the in-repo hooks directory, moving the stage to `NeedsHumanReview` naming the paths.
- **Provider-aware usage reporting** — `loom usage` normalizes Claude transcripts, Codex rollouts and execution receipts into one versioned provider ledger that never sums the two providers, selected with `--provider claude|codex|all` and bounded with `--since`/`--until`; `--claude-root`, `--codex-root`, `--receipts-root` and `--forward-receipts-root` read explicit telemetry roots without falling back, and successful rate-limit polls now append a bounded 30-day quota history the report reads offline.
- **Offline policy comparison** — `loom usage --compare <artifact.json>` evaluates baseline/candidate run pairs before any transcript discovery, reporting separate token-proxy and subscription verdicts, rejecting any quality or latency regression rather than averaging it away, and exiting 0 supported, 1 rejected, 2 inconclusive.
- **One owned wait for subagents** — `loom subagents watch` now requires `--worker claude:<agent-id>` or `--worker codex:<unit-id>` per worker, binds that exact set once, holds a single lease per parent session, and prints one initial and one terminal record; exits are 0 success, 2 deadline, 3 failed or cancelled, 4 already waiting or busy, 5 unknown identity, and 6 a hung worker whose transcript or job stopped moving past `--stall-secs` (default the stage's `subagent_timeout_secs`, else 600). The transcript-polling watch is gone; `list` and `harvest` stay one-shot diagnostics.
- **Exact Codex forward identity** — each forward is bound to one companion job through a minted invocation id and settles on its own lifecycle record rather than a newest-job scan; `loom subagents wait --receipt <id>` waits on one forwarded job without starting or changing it, `loom usage` joins usage rows to that identity, and the forwarding wrapper cancels a job still running at 540 s and exits 124 with `timed_out`.
- **Verified completion and loop recovery** — a stage completes only on an attested, token-authenticated evidence record that survives handoff merges, so a session that finished its work but died before the daemon saw it no longer loops; resumed stages converge back to `Executing`, a repeated attested completion failure parks the stage at `NeedsHumanReview` once its writer is confirmed gone, every session records why it ended separately from its status, and `loom status`, `loom status --live` and the web dashboard render completion-pending, blocked and exit reasons ahead of generic activity.
- **Configurable stage models and efforts** — a `[models]` section in `~/.loom/config.toml` and `.loom/work/config.toml` sets the model and reasoning effort per stage type (`standard`, `knowledge`, `knowledge-distill`, `integration-verify`), and `[pressure]` gains an effort for each of its three slots with matching `--claude-effort`, `--codex-effort` and `--address-effort` flags on `loom pressure`. Both sections resolve key by key — stage field, then project, then user, then built-in — so a project section that sets one key lets the rest fall through.
- **Typed configuration editing** — the terminal editor and web settings dialog now preserve booleans and numbers as native TOML/JSON values, validate numeric and text input, and present booleans and enumerations as controls that can be cycled without free-form parsing.
- **Settings dialog as tier lanes** — the web dashboard's settings dialog shows built-in, user and project side by side as three lane columns with model and effort paired on one row, collapsing to one card per row below 700px, and covers all eighteen config keys with a project tier for the sixteen that have one.
- **Dashboard themes and desktop notifications** — the settings dialog gains a dashboard section kept only in the browser's `localStorage`, with a picker for four themes (Ledger, Aubergine, Pacific, Graphite) and a switch that raises an OS notification when a stage needs a human, needs a handoff, or the run finishes. Notifications need a secure context (`https`, `localhost` or a loopback address), so the switch disables itself and says why when the dashboard is served over plain HTTP to a non-loopback host.
- **Remote dashboard access** — `loom status --web --host <address>` binds the dashboard to an interface other than `127.0.0.1` (a concrete address or a wildcard); a non-loopback bind mints a startup token and requires its cookie on every route, with `Host`/`Origin` checked against the connection's own address. The bind stays plain HTTP, so the token and cookie are visible to anyone who observes the connection.
- **Knowledge source-evidence checking** — `loom knowledge check --strict-evidence` exits non-zero when a knowledge file's declared sources changed or cannot be assessed, across committed, staged, unstaged, untracked, deleted and renamed paths; unavailable evidence is reported as a review issue instead of passing silently.
- **Context-admission hooks** — an authorized typed subagent spawn gets a scoped brief appended after its prompt byte-for-byte; a repeated file read is warned or denied only when a receipt proves the earlier read was delivered, with edits and compactions resetting eligibility; the poll guard counts `loom subagents list` and names the exact wait to use instead; and the skill trigger mandates reading a `SKILL.md` in full only on an exact name or multi-word keyword match.
- **Worker-ownership preflight** — plan structural validation parses a stage description's worker/files-owned table and warns when two workers claim the same path or a claim falls outside the stage's declared `files`.
- **Plan verification for stage-sandbox hazards** — `loom plan verify` rejects masked exit statuses, dynamic `HOME`, bare `mktemp -d`, unusable `allow_write` grants and invalid or duplicate stage `skills:` entries; it warns on network tools, plan-directory reads, hardcoded temporary paths and single-search criteria that already pass at `HEAD`.
- **Knowledge hygiene commands** — `loom knowledge check` can write and consume a structural-issue baseline, enforces tier-2 file and section limits, and adds `delete-section` plus section lifecycle annotations. `loom memory pending --group` separates corrections, mistakes, decisions and other notes, while malformed mistake and stale-knowledge notes are rejected at entry.
- **Resident-context peaks in `loom usage`** — a `peaks` section reports main and subagent p50, p90 and max by scope, the share above 250k and 400k tokens, and subagents that never grew beyond boot cost.
- **A load-on-demand orchestration skill** — delegation cost, briefs, ownership, waits and commit timing move from the always-loaded doctrine into `loom-orchestration`; spawn guards prepend the required worker preamble, share read receipts across a session tree, and keep skill suggestions evidence-based and once per session.
- **More usable browser terminals and stage pages** — viewers can scroll terminal history and double-click to take control, stage pages expose their terminal directly, control cues state the available action, and the ledger expands recent activity when no stage needs attention.

### Changed

- **Project settings suppress generated attribution** *(unreleased)* — Loom's project settings now add empty commit and pull-request attribution values, while preserving any explicit repository attribution block.
- **Unconfined runs and spawns are refused** — `loom init` and `loom run` reject a plan that disables the sandbox, allows unsandboxed escape or requests bypass permissions, and `loom run` additionally refuses drifted hooks, a `LOOM_BIN` or hooks directory under a writable root, and loom hooks registered inside the repository; every spawn repeats the host checks and a refusal blocks the stage as a sandbox setup failure. Loom no longer writes the operator's `.claude/settings.local.json`, recording approvals in its own state instead, and the no-op `--allow-unsafe-plan` flag on `loom init` is removed.
- **Pre-commit refuses partial staging** — a path with both staged and unstaged hunks is now named and rejected before any formatter runs, rather than silently committed with its full working-tree content.
- **Stage-type model and effort defaults** — `standard` now runs at `high` effort and `knowledge` at `medium` rather than `xhigh`, and `knowledge-distill` runs on `sonnet` at `high` rather than `opus`; `integration-verify` stays `opus`/`xhigh`. Every one of these is overridable through `[models]`.
- **Delegation follows task cost** — a main agent may make only a narrowly bounded change itself; larger work goes to the cheapest capable tier, including a Haiku tier for mechanical edits, while engineer agents remain leaves and two-level coordinators are spawned explicitly.
- **Retrieval protects names and measures delivered precision** — terms carried by knowledge headings or aliases survive corpus stopwording, stub-only and unnamed queries abstain, and `loom knowledge eval` scores prompt-mode precision over the pack the hook would actually deliver.
- **Configuration beats sticky state files** — the `.loom/work/terminal-backend-fallback` marker is gone and the configured backend is the only input: `loom run` refuses to start when tmux is configured but not on `PATH`, and a tmux spawn failure blocks the stage instead of silently switching to native. A crash that looks like a rejected `--remote-control` flag now disables Remote Control in memory for the rest of the daemon run and retries without it, writing no `remote_control-unsupported` marker.
- **`loom diagnose` removed** — the command wrote a prompt into the signals directory and never started a session; a stage that runs out of retries now points at `loom stage retry <id>`.
- **Hooks directory renamed** — the repository's `hooks/` directory is now `loom-hooks/`, so installed hook paths and any settings referencing them name `loom-hooks/<hook>.sh`.
- **Dashboard restyle** — the web dashboard moves to a darker aubergine ground with an amber accent in both themes, a white wordmark in dark mode, and a terminal panel that marks handed-over control with a sliding mode key and a red tape ring around the well.
- **Reachable dashboard addresses** — wildcard and interface binds now print concrete bootstrap URLs an operator can open instead of an unusable `0.0.0.0` or `[::]` address.
- **Reliable installation and self-update** — the source installer works when piped from `curl`, development builds no longer claim every published release is newer, and `loom update` resolves releases through GitHub's web redirects instead of the anonymous REST API's shared rate limit.
- **Safe cleanup of live state** — `loom clean --all`, state cleanup and reinitialization stop the active daemon before replacing its state directory; a daemon also detects that its lock belongs to a replaced directory and exits instead of writing into a detached tree.
- **Relay recovery after missed hook delivery** — relay sweeps recover eligible request tickets that were written successfully but whose output line never reached `PostToolUse`, without applying an already-recorded request twice.
- **Waiting stages stay waiting** — a subagent stop heartbeat no longer resumes a main session that is genuinely waiting for user input.
- **Completion and file guards avoid false positives** — inert heredoc bodies remain data, interpreter-fed heredocs remain executable, and edit/file advisories apply only inside the stage and evidence conditions they govern.
- **Repository initialization recovers from stale Git metadata** — before initializing an unrecognized repository, `loom init` removes stale `.git/config.lock` and `.git/HEAD.lock` files and moves an unreadable `.git/config` to a timestamped backup; directories with lock-file names and other `.git` contents are preserved.
